## 1. どうやって作ったか

`build_v817.py` が V816.xlsm の OOXML を直接書き換えます。openpyxl での保存は使っていません。

図形、コメント、webextensions などが失われるためです。

結果として **98パーツ中 9パーツだけが変更**され、残り 89 パーツはバイト単位で同一です。

| 検証項目 | 結果 |
|---|---|
| パーツ数 | 98 → 98（欠落・追加なし） |
| zip 整合性 | OK |
| `xl/vbaProject.bin` | **バイト単位で一致**（VBA は無改変） |
| 全 XML の整形式チェック | 全パーツ OK |
| 書き換えた数式 | 6,312 件 / 構文エラー 0 件 |
| 循環参照 | なし（`O ← M,N,R` / `R ← N,P,Q` / `S ← O` の一方向） |

変更されたパーツ: `sheet1(管理)` `sheet7(分析)` `sheet8(売分析)` `sheet17(自動注文決済)`
`sheet18(取扱説明書)` `sheet22(→V817変更履歴)` `sheet23(V811設定)` `workbook.xml` `app.xml`

> LibreOffice による再計算テストは実施できていません。LibreOffice はこのブックを

## 3. シートごとの変更

### 管理

| 列 | 変更内容 |
|---|---|
| M / N | V811設定の損切幅から算出。呼値丸め（買=切り捨て / 売=切り上げ）は維持 |
| P / Q | 「直近10日」固定窓 → **建玉日起点**の高値・安値に変更 |
| O | S列への参照をやめ売却日T列を見る（S列との**循環参照を解消**） |
| R | 建玉後高安値でトレーリング。発動・幅を H8・H9 から取得 |
| S | O列から導出。閾値のベタ書き（0.06/0.05/0.045/-0.03/-0.04）を廃止 |
| AE | `WORKDAY(購入日,12)` → `WORKDAY(購入日,V811設定!B6)`（10営業日に統一） |
| Y | **推奨株数を新設**。0のときは「⛔1単元でも超過」と表示 |
| 1〜2行目 | 保有件数・含み損益を SUMIFS / COUNTIFS 化（ステータス文字列に依存しない） |

**S列の出力文字列に「損切推奨」「STOP推奨」を含めました。**
これにより既存の `Module1.損切りアラート` が **VBA を書き換えずに機能する**ようになります。
V816 では S列が「🔴損切り」しか出さず、VBA は「損切推奨」を探していたため、
保有銘柄が何%下がっていても毎回「全ポジション正常です」と表示されていました。

G列（購入数量）の実績値は履歴保持のため書き換えていません。新規建玉時に Y列を見てください。

### 分析 / 売分析

R・S列 204行のベタ書き（`×1.08/×0.96`、`×0.92/×1.04`）を V811設定連動に置換。
3行目だけ残っていた `×1.05/×0.95`（TOPIX行）も解消しました。
厳選TOP2!K・L列はここを INDEX 参照しているため自動で追随します。

### 自動注文決済

- **C54 エントリートリガーを 1 → 0**。決済トリガー C44 を書くマクロが存在せず、
  「買いだけ自動で出て決済は絶対に出ない」状態だったため停止しました。
  再開する場合は `=IF(C34="✓エントリー可",1,0)` に置き換えてください。
- C17〜C21 を V811設定連動に。C24 に銘柄 ATR を追加。
- C40 を `C11+C21`（暦日）→ `WORKDAY(C11,C21)`（営業日）に。

### 取扱説明書

セル番地のずれ（説明書 C16＝ストップロス／実際は C17）と数値を訂正し、
`CheckSwingTrailing` / `ResetSwingTracking` が**このブックに存在しない**旨を明記しました。

### Sheet3 → V817変更履歴

変更内容・根拠・設定プリセット・許容損失額の対照表を記載しました。

## 4. 許容損失額を 40,000円にした理由

推奨株数を厳格に守らせると、**1単元でも予算を超える銘柄は建てられません**（＝見送り）。
銘柄管理300銘柄の株価は中央値 2,969円・第3四分位 5,240円、単元は100株です。

| B5 | ATR連動 | ％固定 −6% | ％固定 −4%（V816の幅） |
|---|---|---|---|
| 20,000円 | 見送り 59% | 59% | 33% |
| 30,000円 | 41% | 33% | 10% |
| **40,000円 ★採用** | **29%** | 16% | 6% |
| 50,000円 | 20% | 10% | 4% |
| 100,000円 | 6% | 2% | 2% |

見送りが出るのは ATR連動のせいではなく、**リスク上限を実際に守らせたため**です。
従来の −4% 固定でも B5=20,000円なら 33% が見送りになります（V816 では上限が無視されていた）。

実建玉49件での効果:

| | リスク中央値 | 最大 | 上限超過 |
|---|---|---|---|
| V816（100株固定・損切4%） | 13,480円 | **228,000円** | 3件 |
| V817（推奨株数連動） | 31,932円 | 36,671円 | **0件** |

**B5 と H3 はどちらもセル1つで変更できます。** 挙動の変化を最小にしたい場合は
`B3=0.04 / B4=1.5 / H3=0` に戻せば V816 の −4%/+6% を再現しつつ、
設定の一元化と配線修理だけを効かせられます。

## 5. このブックでは直せなかったもの

`vbaProject.bin` はコンパイル済み p-code を含むため、外部から安全に書き換えられません。
以下は VBE での手作業が必要です。手順は `patch/差し替え箇所.txt` を参照してください。

| 対象 | 内容 |
|---|---|
| 買抽出v13!O・P列 | `Mod_買抽出v13.bas:964-965` の `×1.08 / ×0.96` を VBA が毎回書き込む |
| 売抽出v13!O・P列 | `Mod_SellExtrac.bas:1022,1024` の `×0.92 / ×1.04` も同様 |
| Mod_買抽出_順張りVWAP / Mod_売抽出_下降VWAP | 同じ定数が重複（使用している場合のみ） |
| Mod_KanriSheet | 現行と別レイアウトの管理シートを作り直す。実行しないこと |

`patch/Mod_ExitParams.bas` をインポートすると `ExitTP()` / `ExitSL()` / `SuggestQty()` /
`AtrPct()` が使えるようになり、上記2行の差し替えだけで抽出シートも V811設定に連動します。

その他、修正していないもの:

- **管理!AF・AG列** — 未到達時に 1900/1/1 と表示される件は配列数式のため未修正（判定 AH列は正しく動作）
- **呼値テーブル** — TOPIX100 銘柄は実際の刻みが異なる（例: 57,000円は実際50円刻み、数式は100円刻み）
- **エントリー側のロジック** — 本件は出口の話に限定しています

## 6. 前提と限界

パラメータの根拠は 300銘柄 × 250営業日から作った 32,576件の約定シミュレーション
（窓抜け・往復手数料0.10%・同一日両到達は損切優先）です。以下に留意してください。

- 検証母集団は「すでに監視対象として選ばれた」300銘柄で、期間中に10日平均 **+1.82% の上方ドリフト**があります。
  広い損切・長い保有が有利に出るのは大部分がこのドリフトの取り込みで、急落局面では逆になります。
- 期間は 2025/07/29〜2026/08/06 の 250営業日、下落→反発の1サイクルのみです。
- スリッページ・貸株料・約定不成立・逆指値の呼値制約は未考慮で、実績はここから下振れします。
- だからこそ **B5（1回の許容損失額）を守ること**が、パラメータの微調整より優先されます。
