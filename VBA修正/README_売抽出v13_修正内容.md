# 売抽出v13 の不具合調査と修正（sogo_baibai_V1.xlsm）

調査日: 2026/08/31 / 対象: `sogo_baibai_V1.xlsm`

---

## 1. ご指摘の「銘柄名称が出ない」— 原因は2つ重なっていました

### 実際にシートに入っていた値

`売抽出v13` の D列（銘柄名称）を直接読み出すと、こうなっていました。

| 行 | C列 銘柄コード | D列 銘柄名称 |
|----|---------------|-------------|
| 4  | 3936          | **-3936**   |
| 5  | 7741          | **-7741**   |

名前が「空欄」なのではなく、**コードの符号を反転した数値**が入っていました。

### 原因① 名前が取れなかったときの逃げ道が、Excelに数値化されていた

`Mod_SellExtrac` にこの1行がありました。

```vba
If meiName = "" Then meiName = "(" & code & ")"     ' → "(3936)"
```

`"(3936)"` は Excel の会計表記では **マイナス3936** です。
`.Value = "(3936)"` と書き込むと Excel が勝手に数値 `-3936` に変換します。
つまり「名前が取れなかった」ことを知らせるはずの表示が、
数字に化けて原因を隠していました。買抽出v13 側も同じコードでした。

**修正**
- 名前が取れないときは `3936（名称未取得）` と全角カッコで書く（数値化しない）
- 書き込む直前に D列の表示形式を `"@"`（文字列）に固定する
- D列全体も文字列書式に固定するので、今後この化け方は起きません

### 原因② そもそも銘柄名の出所が RSS 1本しかなかった（これが本丸）

銘柄名をたどると、このBOOKでは **すべて1か所** に行き着きます。

```
銘柄管理!C6  = @RssMarket($B6,"銘柄名称")     ← RSSが生きている時だけ値が返る
   ├─ 終値!B245 = 銘柄管理!C245               ← 参照しているだけ
   └─ 分析!D3   = 銘柄管理!C5                 ← 参照しているだけ
```

保存時点のブックを読むと、`銘柄管理!C列` は **300行すべて "エラー"** でした。
RSS が止まっていると銘柄名の供給源が全滅します。

さらに `終値!B列` を調べると、

- 212銘柄 … `三井金属` のように**文字列で焼き付け済み**（RSSが死んでいても出る）
- **87銘柄 … `=銘柄管理!C245` という式のまま**（RSSが死ぬと "エラー" か空）

ご指摘の 3936 / 7741 はどちらも後者の87銘柄側でした。
売り抽出は**夜間（15:30以降）は保存済みデータ版で動く**設計なので、
この87銘柄が引っかかると必ず名前が出ません。

**修正：銘柄名キャッシュを新設（`Mod_銘柄名キャッシュ`）**

一度でも取れた正しい銘柄名を、`銘柄管理` の **AD列（非表示）** に文字列で貯めます。

- 取り込み元は ① 銘柄管理C列(RSS) ② 終値B列 ③ 分析D列 ④ 検証明細D列 の順
- 正しい名前が既に入っている行を、空や "エラー" で**上書きしません**
- 抽出のたびに自動で育つので、普段は意識不要です

いま手元のBOOKの状態で試算すると、
**212銘柄は即座に、検証明細から追加で22銘柄、合計234銘柄がRSSなしで復旧**します。
残り65銘柄は、RSSが繋がっている取引時間中に一度抽出（または
`銘柄名キャッシュ更新` ボタン）を実行すれば埋まり、以後は夜間でも出ます。

「エラー」「#N/A」「数値」「空」は名前として無効と判定するようにしたので、
`エラー` がそのまま銘柄名欄に出ることもなくなります。

## 2. あわせて見つかった不具合

### ★A 取引時間中は見出し行が消えて、データが1行ずれていた（重症）

RSS現在値版（**9:00〜15:30 に走る方**）だけ、こうなっていました。

```vba
For hc = 0 To 17
    With extWs.Cells(4, hc + 1)      ' ← 見出しを 4行目 に書く
...
extWs.Range(extWs.Cells(4, 1), ...).ClearContents   ' ← その4行目を直後に消す
...
Dim outRow As Long: outRow = 4       ' ← データも 4行目 から書く
```

**見出しを書いた直後に、その見出しを消していました。**
保存済みデータ版は正しく3行目に書いているので、日中と夜間で
シートの構造が変わってしまう状態でした。
（見出し語も日中は「コード／銘柄名」、夜間は「銘柄コード／銘柄名称」と不一致）

**修正**: 見出し出力を共通ルーチン `S_ヘッダー出力` に一本化し、
両方とも3行目・同じ見出し語に統一。クリアは4行目以降のみ。

### ★B 空行削除がシート行ごと削除で、右側の推奨指値ブロックを巻き上げていた

```vba
extWs.Rows(delRow).Delete       ' ← A列からXFD列まで、行まるごと削除
```

`売抽出v13` は **U〜AC列に推奨指値ブロック**があります。
行まるごと削除すると、そのブロックだけ上にズレて別銘柄の指値が並びます。

**修正**: A〜R列だけを対象に詰める `S_空行を詰める` に置換。

### ★C 再抽出しても推奨指値（U〜AC列）が前回のまま残っていた

現ファイルが実際にその状態でした。

| | A〜R列（今回の抽出） | U〜AC列（前回の推奨指値） |
|---|---|---|
| 4行目 | コード3936 現在値 **153** | 基準終値 **3191** ATR 220.2 |
| 5行目 | コード7741 現在値 **24465** | 基準終値 **4937** ATR 199.6 |

隣に**まったく別銘柄の指値**が並んでいます。危険な表示です。
抽出のクリア範囲がA〜R列までで、推奨指値は別ボタンだったためです。

**修正**
- クリア時に U〜AC列 も一緒に消す
- 抽出の最後に推奨指値を自動で作り直す
  （`Mod_推奨指値` に無言実行の入口 `推奨指値_売抽出v13_無言` を追加）

### ★D 2件抽出のとき、スコア順ソートが一度も走っていなかった

```vba
If outRow > 6 Then    ' 2件だと outRow = 6 なので False
```

既定は**上位2件抽出**なので、実質いつもソートされないまま
「上位N件だけ残す」処理に進んでいました。順位が正しくない可能性があります。

**修正**: `If outRow - 4 >= 2 Then`

### ★E 途中でエラーが出ると Excel が壊れた状態で放置されていた

エラーハンドラが無く、落ちると以下がそのまま残ります。

- `Application.Calculation = xlCalculationManual`（再計算が止まる）
- `Application.ScreenUpdating = False`（画面が固まる）
- `Application.StatusBar`（変な文字が出っぱなし）
- 売抽出v13 / 銘柄管理 / 分析 の**シート保護が解除されたまま**

**修正**: 入口で保護状態と再計算モードを控え、
正常終了・異常終了どちらでも `S_後始末` で必ず元に戻す。
中断時はエラー番号とメッセージを表示します。

### ★F RSS版だけ「出来高5日平均」の自前計算が抜けていた

保存済みデータ版にはあるフォールバックが RSS 版だけ無く、
分析シートに行が無い銘柄は**出来高倍率が常に 0 倍＝加点ゼロ**でした。

**修正**: 共通関数 `S_出来高5日平均` を両方から呼ぶ。

### ★G RSS版に「銘柄管理シートが無い」チェックが抜けていた

保存済みデータ版にはある `If mws Is Nothing` の確認が RSS 版に無く、
シートが無いと `mws.Cells(5, 6)` で実行時エラーになります。

**修正**: 同じガードを追加。

### ★H 自動更新ボタンを2回押すとタイマーが多重登録されていた

`売抽出自動更新開始` が古い `Application.OnTime` を解除していませんでした。
押した回数だけ5分ごとに抽出が走ります。

**修正**: 登録前に必ず既存タイマーを解除。

### ★I RSSが止まっていると TOPIX が 0.00% として扱われ、気付けなかった

`銘柄管理!C5`（TOPIX現在値）が取れないと `topixPct = 0` になり、
相場判定が常に【通常】になります。現ファイルの見出しも
`TOPIX: 下落▼ (0.00%) 【通常】` と、下落なのに 0.00% という矛盾した表示でした。

**修正**: 取得できていないときは `※TOPIX未取得(RSS停止中)` と明示。
（判定ロジック自体は変えていません）

## 3. 修正していない、設計上の申し送り

コードを変えると結果が変わるため、報告のみです。

1. **売り側の期待値** — モジュール冒頭のコメントどおり、検証では
   どの設定でもマイナス〜ゼロ近辺です。枠が限られるなら買い側優先が有利、
   という作者自身の結論はそのまま有効です。
2. **利確/損切が固定%** — 売り抽出のO列/P列は終値×0.92 / ×1.04 の固定です。
   一方でコメントとU〜AC列の推奨指値はATRベース。基準が二重です。
3. **EMA75を60日データで計算** — `S_IsPerfectDown` は75日EMAを使いますが、
   読み込んでいるのは60日分だけなので近似値です（買い側も同じ）。
4. **RSIがWilder平滑ではない単純平均** — 一般的なRSIとは値がずれます。
5. **保存済みデータ版とRSS版が500行規模でほぼ二重定義** — 今回★A・★Fのような
   「片方だけ直っている／片方だけ壊れている」の温床です。共通化を推奨します。

## 4. 反映のしかた（VBEでモジュールを入れ替え）

`.xlsm` の中の VBA はバイナリ（vbaProject.bin）なので、
ファイルを直接書き換えず、**VBE で入れ替えて**ください。

1. Excel で `sogo_baibai_V1.xlsm` を開き `Alt + F11`（VBE）
2. 既存の `Mod_SellExtrac` / `Mod_買抽出v13` / `Mod_推奨指値` を
   右クリック →「〜の解放」→ **エクスポートは「いいえ」**（元ファイルは残ります）
3. メニュー「ファイル」→「ファイルのインポート」で、このフォルダの4つを入れる
   - `Mod_銘柄名キャッシュ.bas` ← **新規（必須）**
   - `Mod_SellExtrac.bas`
   - `Mod_推奨指値.bas`
   - `Mod_買抽出v13.bas`
4. VBE の「デバッグ」→「VBAProject のコンパイル」でエラーが出ないことを確認
5. 上書き保存（マクロ有効ブック `.xlsm` のまま）

### 入れ替え後、最初にやること

- **`銘柄名キャッシュ更新`** を一度実行（マクロ一覧から実行できます）
  → いま出せる234銘柄分の名前が `銘柄管理` AD列に保存されます
- すでに `-3936` になっている表示を直したいだけなら
  **`売抽出_銘柄名を直す`**（抽出しなおさず名前だけ埋め直します）
- 残り65銘柄は、**RSSが繋がっている取引時間中に一度**抽出するだけで埋まります

### 追加されたマクロ

| マクロ名 | 用途 |
|---|---|
| `銘柄名キャッシュ更新` | 取れる銘柄名をキャッシュに保存（ボタン割り当て推奨） |
| `売抽出_銘柄名を直す` | 売抽出v13の銘柄名だけ埋め直す（抽出はしない） |
| `名称セル修復_全抽出シート` | 買抽出v13/売抽出v13/厳選TOP2 の名前をまとめて修復 |
| `推奨指値_売抽出v13_無言` | 抽出処理から自動で呼ばれる（手動実行も可） |
| `推奨指値_買抽出v13_無言` | 同上（買い側） |

### 元に戻したい場合

差し替えたのは VBA モジュールだけです。手順2で解放したモジュールは
`元モジュール_バックアップ/` に元のコードを置いてあるので、
同じ手順でインポートし直せば完全に戻せます。

## 5. 補足：ファイルの文字コードについて

`.bas` は **Shift-JIS(CP932) / CRLF** で保存してあります。
これは VBE の「ファイルのインポート」がそのまま読める形式です。
（GitHub 上ではコメントの日本語が文字化けして見えますが、
　Excel に取り込むときは正しく表示されます。
　中身をブラウザで読みたい場合は、このREADMEの説明をご覧ください。）

`.xlsm` 本体は今回**変更していません**。VBAはブック内でバイナリ
(`vbaProject.bin`) として格納されているため、外部から安全に書き換えられません。
そのため「差し替え用のモジュール一式」という形でお渡ししています。
