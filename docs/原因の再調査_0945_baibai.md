# `0945_baibai.xlsm` 原因の再調査

## 前提の訂正

初回の調査は `打ち出のこづち_0615MOD整理 改善 .xlsm` に対して行ったものです。
リポジトリに `0945_baibai.xlsm` が無かったため、同系統のブックとして代用しました。

しかし VBE の画面を確認したところ、**両者は全く別のブック**でした。

| | 打ち出のこづち（解析済み） | 0945_baibai（実際の症状ブック） |
|---|---|---|
| 標準モジュール | 20本以上（Mod_SellExtrac 等） | `Module1` / `Module2` の2本のみ |
| シート | 銘柄管理 / 買抽出 / 分析 / 始値 … | 使い方 / RSS取得 / 稼働モニター / 売買時刻マトリクス … |
| `Application.OnTime` | 8箇所 | **なし** |

したがって **`Fix_OnTime_Cleanup` は `0945_baibai.xlsm` では効果がありません。**
OnTime 予約が存在しないため `CancelAllTasks` は常に空振りします。
害はないので残して構いませんが、これは解決策ではありません。

---

## OnTime 以外に「ブックが勝手に開く」経路

原因を以下の6系統に絞って順に潰します。**A〜C が本命**です。

### A. タスク スケジューラ ★最有力

ファイル名の `0945` が **09:45（寄り付き後の売買時刻）** を示していること、
シートに「稼働モニター」「売買時刻マトリクス」があることから、
**時刻起動の自動売買として意図的にタスク登録された可能性が高い**です。

確認: `Win`+`R` → `taskschd.msc` → 「タスク スケジューラ ライブラリ」
または `tools/診断_自動起動.ps1` の `[1]` セクション。

### B. XLSTART フォルダ / 起動時フォルダ

```
%APPDATA%\Microsoft\Excel\XLSTART
```
ここに実体やショートカットがあれば、Excel を起動するたびに必ず開きます。

`ファイル → オプション → 詳細設定 → 全般 → 起動時にすべてのファイルを開くフォルダー`
も同様。

### C. Windows「サインイン後にアプリを自動的に再起動する」

Windows 10/11 の既定で **ON** の場合があります。
シャットダウン時に開いていた Excel が、次回サインインで自動復活します。
「PCを立ち上げたら勝手に開いていた」という症状ならこれが濃厚です。

`設定 → アカウント → サインイン オプション`
→ **「サインイン後にアプリを自動的に保存して再起動する」を OFF**

### D. VBS / BAT スクリプト、レジストリ Run キー

`.vbs` や `.bat` から `Excel.Application` 経由で開かれているケース。
スタートアップフォルダと `HKCU\...\CurrentVersion\Run` を確認。

### E. DDE / RTD（MarketSpeed II RSS）

本ブックには「RSS取得」シートがあり、楽天 MarketSpeed II と連携しています。
外部アプリからの DDE 要求で Excel がブックを開くことがあります。

`ファイル → オプション → 詳細設定 → 全般`
→ 「他のアプリケーションとの DDE を無視する」にチェックを入れると切り分けできます
（RSS 連携も止まるので、切り分け後は必ず戻すこと）。

### F. `Workbook_Open` 以外の VBA 自動実行

`Module1` / `Module2` / `ThisWorkbook` に以下が無いか確認:

- `Auto_Open` / `Auto_Close`
- `Workbooks.Open`（別ブックを開く）
- `SetTimer` / `KillTimer` の Win32 API 宣言（OnTime を使わないタイマー実装）
- `CreateObject("Excel.Application")`
- `CreateObject("WScript.Shell")` / `Shell(`
- `CreateObject("Schedule.Service")`（VBA からタスク登録している場合）

> **VBE の検索は範囲指定に注意**
> `Ctrl`+`F` のダイアログで、対象が「現在のプロシージャ」や「現在のモジュール」に
> なっていると他モジュールを検索しません。必ず **「カレント プロジェクト」** を選んでください。

## 診断ツール

本コミットに2つ同梱しています。どちらも**読み取りのみ**で設定は変更しません。

### 1. `tools/診断_自動起動.ps1` — Windows側（A〜D を一括確認）

PowerShell で実行:

```powershell
powershell -ExecutionPolicy Bypass -File .\診断_自動起動.ps1
```

デスクトップに `自動起動診断_Windows_yyyyMMdd_HHmmss.txt` が出力されます。
確認内容: タスクスケジューラ / XLSTART / AltStartup / スタートアップ /
Run レジストリ / RestartApps 設定 / ファイル検索 / Excelプロセス / イベントログ

### 2. `vba/Diag_AutoStart.bas` — ブック側（E〜F を確認）

`0945_baibai.xlsm` の VBE でインポートし、`Alt`+`F8` → **`自動起動診断`** を実行。
デスクトップに `自動起動診断_yyyymmdd_hhnnss.txt` が出力されます。
確認内容: 起動フォルダの実体 / 開いているブック / アドイン / COMアドイン /
全モジュールの `OnTime`・`Workbook_Open`・`Shell`・`CreateObject` 出現行 / 外部リンク

> `[6] VBA モジュール一覧` が読み取れない場合は、
> `ファイル → オプション → トラスト センター → トラスト センターの設定 →
> マクロの設定 → 「VBA プロジェクト オブジェクト モデルへのアクセスを信頼する」`
> にチェックを入れて Excel を再起動してください。
>
> なお、既に `Fix_OnTime_Cleanup` を取り込んでいる場合、そのモジュール内の
> `Application.OnTime` が3件ヒットしますが、これは診断ツール自身のコードなので
> **無視してください**。

## 切り分けのショートカット

診断を待たずに、症状の出方で当たりを付けられます。

| 症状 | 疑うべき原因 |
|---|---|
| PCを起動/サインインした直後に開いている | **C**（アプリ再起動設定）または **B**（スタートアップ） |
| 決まった時刻（09:45 など）に開く | **A**（タスクスケジューラ） |
| Excel で別のファイルを開くと一緒に開く | **B**（XLSTART / 起動時フォルダ） |
| 閉じた数十秒〜数分後に開き直す | **F**（Win32 SetTimer 等のタイマー） |
| MarketSpeed II を起動すると開く | **E**（DDE / RTD 連携） |

## 確実に特定するには

`0945_baibai.xlsm` そのもの、または以下3つのコード全文があれば断定できます。

- `ThisWorkbook`
- `Module1`
- `Module2`

VBE で各モジュールを開き、`Ctrl`+`A` → `Ctrl`+`C` でコピーできます。
