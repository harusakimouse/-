# `0945_baibai.xlsm` 自動起動 — 恒久対策手順

所要時間: 15〜20分 / 作業対象: `0945_baibai.xlsm`（および同じVBAを持つ全コピー）

> 対策の中身は「`Application.OnTime` の予約を台帳に記録し、ブックを閉じるときに全件解除する」ことです。
> 原因の詳細は `docs/0945_baibai_自動起動_原因調査.md` を参照してください。

---

## STEP 0. 事前準備（必須）

### 0-1. バックアップを取る

作業前に必ず `0945_baibai.xlsm` をコピーして退避してください。
VBE の編集は Ctrl+Z で戻せません。

```
0945_baibai.xlsm  →  0945_baibai_backup_20260830.xlsm
```

### 0-2. 残っている予約を全部消す

**これを飛ばすと、対策後も一度だけ勝手に起動します。**
既存の予約は Excel プロセスのメモリ上にあり、台帳に記録がないため新モジュールでは解除できません。

1. 開いている Excel を全て閉じる
2. `Ctrl` + `Shift` + `Esc` でタスクマネージャーを開く
3. 「詳細」タブで **`EXCEL.EXE` を全て選択 → タスクの終了**
   （「プロセス」タブに Excel が残っていないことも確認）

> Excel プロセスが完全に消えた時点で、溜まっていた OnTime 予約は全て消滅します。

### 0-3. マクロを無効にして開く

1. Excel を起動（空のブックが開く）
2. **`Shift` キーを押しっぱなしのまま** `0945_baibai.xlsm` を開く
3. セキュリティの警告バーが出ても **「コンテンツの有効化」は押さない**

これで `Workbook_Open` が実行されず、新しい予約が入りません。この状態で編集します。

## STEP 1. 対策モジュールを取り込む

1. `Alt` + `F11` で VBE（Visual Basic Editor）を開く
2. 左のプロジェクトエクスプローラーで **`VBAProject (0945_baibai.xlsm)`** を選択
   （※他のブックのプロジェクトを選ばないよう注意）
3. メニュー **ファイル → ファイルのインポート**（`Ctrl` + `M`）
4. `vba/Fix_OnTime_Cleanup.bas` を選択して開く
5. 「標準モジュール」の下に **`Fix_OnTime_Cleanup`** が追加されたことを確認

> リポジトリからファイルを落とせない場合は、標準モジュールを新規挿入
> （挿入 → 標準モジュール）して、`Fix_OnTime_Cleanup.bas` の中身を貼り付け、
> モジュール名を `Fix_OnTime_Cleanup` に変更しても構いません。
> その際、先頭行の `Attribute VB_Name = "Fix_OnTime_Cleanup"` は貼り付けないでください
> （インポート時専用の行で、直接貼るとエラーになります）。

---

## STEP 2. `ThisWorkbook` に閉じる処理を追加する ★最重要

プロジェクトエクスプローラーで **`ThisWorkbook`** をダブルクリックし、
既存の `Workbook_Open` の**下**に以下を追加します。

```vba
Private Sub Workbook_BeforeClose(Cancel As Boolean)
    ' 予約を残したまま閉じると Excel がブックを勝手に開き直すため、
    ' 閉じる前に必ず全件解除する。
    On Error Resume Next
    Call CancelAllTasks
    On Error GoTo 0
End Sub
```

**この STEP 2 だけでも「15:31 に勝手に起動する」症状は止まります。**
STEP 3 は、5分/30秒タイマーの停止ボタンを正しく効かせるための修正です。

---

## STEP 3. 既存の `Application.OnTime` を置き換える

`Ctrl` + `F` →「対象: カレント プロジェクト」で `Application.OnTime` を検索すると
以下の8箇所が見つかります。順に置き換えてください。

### 3-1. `ThisWorkbook` — `Workbook_Open`（3箇所）

```vba
' 変更前
Application.OnTime 発火時刻, "日次更新_自動"
Application.OnTime 発火時刻 + TimeValue("00:00:30"), "売抽出更新"
Application.OnTime 発火時刻 + TimeValue("00:01:00"), "株価抽出"

' 変更後
ScheduleTask 発火時刻, "日次更新_自動"
ScheduleTask 発火時刻 + TimeValue("00:00:30"), "売抽出更新"
ScheduleTask 発火時刻 + TimeValue("00:01:00"), "株価抽出"
```

### 3-2. `Mod_SellExtrac` — 5分タイマー（3箇所）

```vba
Public Sub 売抽出自動更新開始()
    NextSellRunTime = Now + TimeValue("00:05:00")
    ScheduleTask NextSellRunTime, "売抽出タイマー実行"        ' ← 変更
    MsgBox "自動更新開始（5分ごと）", vbInformation
End Sub

Public Sub 売抽出タイマー実行()
    Call 売り候補抽出
    NextSellRunTime = Now + TimeValue("00:05:00")
    ScheduleTask NextSellRunTime, "売抽出タイマー実行"        ' ← 変更
End Sub

Public Sub 売抽出自動更新停止()
    Call CancelAllTasks                                       ' ← 変更（1行に置換）
    MsgBox "自動更新停止", vbInformation
End Sub
```

> **停止処理を `CancelAllTasks` に変える理由**
> 変更前は `NextSellRunTime`（モジュール変数）を使って解除していましたが、
> この変数はブックを閉じた時点で 0 にリセットされます。
> `Application.OnTime` の解除は「時刻とプロシージャ名の完全一致」が必須なため、
> 開き直してから停止を押しても**解除に失敗していました**。
> `CancelAllTasks` は台帳から実際の予約時刻を読むので確実に解除できます。

### 3-3. `Mod_RSS接続状態` — 30秒タイマー（2箇所）

```vba
Public Sub RSS監視開始()
    ' ...（前略）...
    Monitoring = True
    NextMonitorTime = Now + TimeSerial(0, 0, MONITOR_INTERVAL_SEC)
    UpdateStatusSilent
    ScheduleTask CDate(NextMonitorTime), "RSS監視タイマー"    ' ← 変更
    ' ...（後略）...
End Sub

Public Sub RSS監視停止()
    If Not Monitoring Then
        MsgBox "監視は実行されていません。", vbInformation, "停止"
        Exit Sub
    End If

    Call CancelAllTasks                                       ' ← 変更（Application.OnTime 3行を置換）

    Monitoring = False
    MsgBox "RSS接続状態の自動監視を停止しました。", vbInformation, "停止完了"
End Sub

Public Sub RSS監視タイマー()
    If Not Monitoring Then Exit Sub
    UpdateStatusSilent
    NextMonitorTime = Now + TimeSerial(0, 0, MONITOR_INTERVAL_SEC)
    ScheduleTask CDate(NextMonitorTime), "RSS監視タイマー"    ' ← 変更
End Sub
```

> `NextMonitorTime` は `Double` 型で宣言されているため、`CDate()` で明示的に
> `Date` に変換して渡します（暗黙変換でも動きますが、意図を明確にするためです）。

### 3-4. 置換後の確認

もう一度 `Application.OnTime` を検索し、**ヒットが `Fix_OnTime_Cleanup` 内の3箇所だけ**に
なっていれば置換完了です（`ScheduleTask` / `CancelTask` / `CancelAllTasks` の中身）。

## STEP 4. コンパイル確認

VBE メニュー **デバッグ → VBAProject のコンパイル**

エラーが出ないことを確認してください。よくあるエラー:

| エラー | 原因と対処 |
|---|---|
| `変数が定義されていません` で `ScheduleTask` が黄色くなる | STEP 1 のモジュール取り込みが未完了。プロジェクトを確認 |
| `名前が適切ではありません: Fix_OnTime_Cleanup` | 同名モジュールが既にある。古い方を削除 |
| `プロシージャ名が適切ではありません` | `Attribute VB_Name = ...` 行を手貼りした。その行を削除 |

## STEP 5. 保存

1. VBE で `Ctrl` + `S`、または Excel 側で上書き保存
2. **必ず `.xlsm`（マクロ有効ブック）のまま保存する**
   `.xlsx` で保存するとマクロが全部消えます

## STEP 6. 動作確認

### 6-1. 予約が記録されるか

1. ブックを一度閉じて、**今度は普通に開く**（コンテンツの有効化を押す）
2. `Alt` + `F8` → `予約状況を表示` を実行
3. 15:31 より前に開いた場合、3件の予約が一覧表示されればOK

```
2026/08/30 15:31:00  →  日次更新_自動
2026/08/30 15:31:30  →  売抽出更新
2026/08/30 15:32:00  →  株価抽出
```

### 6-2. 閉じるときに解除されるか ★本命

1. ブックを閉じる（**Excel 本体は閉じずに残しておく**）
2. Excel の空ブックで `Alt` + `F8` … は使えないので、
   代わりに **10分ほど放置して 15:31 を跨がせる**、もしくは以下の簡易テストを行う

**簡易テスト（推奨・すぐ終わる）**

`ThisWorkbook` の `Workbook_Open` を一時的に書き換え、2分後に発火させます。

```vba
' テスト用に一時的に差し替え
発火時刻 = Now + TimeValue("00:02:00")
```

1. 保存して閉じ、開き直す（=2分後の予約が入る）
2. **すぐにブックを閉じる**（Excel 本体は起動したまま）
3. 3分待つ
4. **ブックが開かなければ対策成功**
5. `発火時刻 = Int(Now()) + TimeValue("15:31:00")` に戻して保存

### 6-3. 台帳シートの確認（任意）

`_OnTimeReg` という非表示シートが自動生成されます。
`xlSheetVeryHidden` なのでシートタブの右クリック「再表示」には出てきません。
中身を見たい場合は VBE のイミディエイトウィンドウ（`Ctrl` + `G`）で:

```vba
ThisWorkbook.Sheets("_OnTimeReg").Visible = xlSheetVisible    ' 表示
ThisWorkbook.Sheets("_OnTimeReg").Visible = xlSheetVeryHidden ' 隠す
```

## STEP 7. 他のコピーにも同じ対策を入れる

同じ VBA を持つブックが複数あると、**対策していないブックが1つでも残っていれば
そのブックが勝手に起動します**。

`.xlsm` を全て洗い出してください（PowerShell）:

```powershell
Get-ChildItem -Path $HOME -Recurse -Include *.xlsm -ErrorAction SilentlyContinue |
    Select-Object FullName, Length, LastWriteTime | Format-Table -AutoSize
```

`0945_baibai.xlsm` / `打ち出のこづち*.xlsm` などが複数出てきたら、
**使わないコピーは別フォルダに退避するか削除**し、
現用の1本にだけ対策を適用するのが確実です。

## STEP 8. VBA以外の自動起動要因を確認（対策後もまだ開く場合）

STEP 1〜7 を終えても勝手に起動する場合、Excel/Windows 側の設定が原因です。

### 8-1. XLSTART フォルダ

エクスプローラーのアドレスバーに貼り付けて確認:

```
%APPDATA%\Microsoft\Excel\XLSTART
```

`0945_baibai.xlsm` の実体やショートカットがあれば移動してください。
このフォルダのファイルは Excel 起動時に必ず開かれます。

### 8-2. Excel の「起動時にすべてのファイルを開くフォルダー」

`ファイル` → `オプション` → `詳細設定` → `全般` セクション
→ **「起動時にすべてのファイルを開くフォルダー」を空欄にする**

### 8-3. Windows のスタートアップ

```
%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup
```

### 8-4. タスクスケジューラ

`Win` + `R` → `taskschd.msc` → 「タスク スケジューラ ライブラリ」
該当ファイルを開くタスクが登録されていないか確認。

### 8-5. 楽天 MarketSpeed II の RSS 連携

本ブックは `xl/volatileDependencies.xml` に RSS 参照を持ちます。
MarketSpeed II 側の設定で Excel 連携が自動起動になっていないか確認してください。

## 補足: 既知の制限

| 事象 | 挙動 |
|---|---|
| Excel を「×」ボタンで終了 | `Workbook_BeforeClose` が発火するので解除される（正常） |
| タスクマネージャーで強制終了 | `BeforeClose` は発火しないが、プロセスごと消えるので予約も消える（問題なし） |
| 閉じる確認ダイアログで「キャンセル」を押した | 予約は解除済みのまま作業続行になる。タイマーを戻したい場合はブックを閉じて開き直す |
| ブック構成が保護されている | `_OnTimeReg` シートを作れず台帳が機能しない。校閲 → ブックの保護 を解除してから STEP 6 を実施 |

---

## 参考: 調査時に確認済みの事実

- VBA 全36モジュールに `Workbook_BeforeClose` / `Auto_Close` は**1件も存在しなかった**
- `Application.OnTime` は全8箇所（`ThisWorkbook`×3 / `Mod_SellExtrac`×3 / `Mod_RSS接続状態`×2）
- 外部リンク（`xl/externalLinks/`）は**存在しない**
- 他ブックを開く `Workbooks.Open` / `Shell` / `CreateObject("Excel.Application")` は**VBA内に一切ない**

→ 他ファイルから呼ばれているのではなく、**このブック自身の OnTime 予約による自己再オープン**が原因。
