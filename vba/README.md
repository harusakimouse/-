# ティック判定ロジック（15:00〜15:20 専用）VBA 完成版

`Tik___V1.xlsm` を完成形にするための VBA 一式です。
RSS の**歩み値（TICK）**を追従して記録し、15:20 に **買い / 売り / 中立** を出して 15:25 のプレクロージングに持ち込みます。

```
15:00:00  歩み値の記録 開始   （ボタン② または 自動予約）
15:00〜   Judge_Results に 最良買気配 / 最良売気配 / スプレッド をリアルタイム表示
15:23〜   ザラバ終盤の大口が入る時間帯（Vol4 がここを見ます）
15:24:00  記録終了 → 自動で判定
15:24:02  買い / 売り / 中立 が色分けで並ぶ   ← ここを見て発注
15:25:00  ザラバ終了 / クロージング・オークション開始
15:30:00  板寄せ約定
```

判定が出てから板寄せまで **約6分**。1銘柄の新規発注と本日返済を入れるには十分な余裕です。

## 0. 文字コードについて（重要）

VBE の「ファイルのインポート」は `.bas` を **ANSI（日本語Windowsでは Shift-JIS）** として読みます。
UTF-8 のままインポートすると、コメントだけでなく **`"買い"` や `"銘柄名称"` などの文字列リテラルも壊れて動作しません**。

このフォルダの `.bas` と `ThisWorkbook_貼り付け用.txt` は **Shift-JIS（CP932）+ CRLF** で保存済みです。
そのままインポートしてください。

> 既に文字化けした状態でインポート済みの場合は、**先に化けたモジュールを全部「解放」（削除）してから**
> 入れ直してください。上書きインポートにはなりません。
>
> なお `README.md` だけは GitHub で読めるよう UTF-8 のままです（インポートしないので影響ありません）。

## 1. 導入手順

1. `Tik___V1.xlsm` を開き、`Alt + F11` で VBE を開く
2. **既存の `Module1` を削除する**（文字化けした `Module_*` があればそれも全部削除）
   （右クリック →「◯◯ の解放」→ エクスポートは「いいえ」）
   *`Module1` を削除しないと `WriteSummary` が二重定義になり「名前が適切ではありません」で止まります*
3. 「ファイル」→「ファイルのインポート」で以下 5 本を取り込む
   - `Module_Config.bas`
   - `Module_Judge.bas`
   - `Module_TickLogger.bas`
   - `Module_Setup.bas`
   - `Module_Import.bas`
4. ツリーの `ThisWorkbook` をダブルクリックし、`ThisWorkbook_貼り付け用.txt` の中身を貼り付け
   （メモ帳などで開くと Shift-JIS なので日本語がそのまま読めます）
5. VBE で「デバッグ」→「VBAProject のコンパイル」がエラーなしなら OK
6. 各銘柄シートの **B3 に証券コード** を入れる（例: `7203`）
7. `Judge_Results` の **「① 準備（表とRSSを作る）」** を押す
8. **各銘柄シートの `AB3` に、お使いの RSS の歩み値数式を入れる**（← 重要。次章）
9. `Judge_Results` の **「歩み値ブロックの確認」** を押して読めているか確認
10. 上書き保存（マクロ有効ブック `.xlsm`）

## 1-2. 自分でやること / 自動でやること

### 最初の1回だけ（自分でやること）

1. `Module1` と古い `Module_*` を解放し、`.bas` 5本をインポート
2. `ThisWorkbook` に `ThisWorkbook_貼り付け用.txt` を貼り付け
3. 各銘柄シートの **B3 に証券コード**
4. `Alt + F8` → **`Setup_All`** を実行
   （**ボタンはこれが自動で作ります**。自分で図形を置く必要はありません）
5. 各銘柄シートの **`AB3` に `RssTickList`** を登録（次章）
6. 上書き保存

### 毎日（自分でやること）

**ブックを開くだけです。**

`AUTO_ARM_ON_OPEN = True`（既定）なので、開いた瞬間に自動開始が予約されます。

| 開いた時刻 | 動作 |
|---|---|
| 14:59:30 より前 | 14:59:30 に自動で記録開始 |
| 14:59:30〜15:24 の間 | 3秒後にすぐ記録開始（判定窓の前なら中で待機） |
| 15:24 より後 | 何もしない（本日の判定時間は終了） |

あとは **15:24 に判定が出る**ので、`Judge_Results` の `判定` 列の色を見て発注するだけです。

ボタンを押す必要があるのは、やり直したいとき（`⑤ ティックログ消去` → `② 記録開始`）や、
検証したいとき（`出来高プロファイル` など）だけです。

### 旧バージョンから乗り換えたとき（1回だけ）

旧バージョンは1行目にタイトルや「判定」を書いていました。今は1行目に触らないので、
その残骸がそのまま残ります。`Alt + F8` → **`CleanupOldLayout`** を1回実行すると、
全シートの1行目の文字と書式が消えてまっさらなメモ欄になります。

> 気配値が `00:00:00` と表示される場合も、旧レイアウトの表示形式が残っているのが原因です。
> 新しい `Setup_All` が表示形式を明示的に戻すので、実行すれば直ります。

### 1行目はメモ欄です

**銘柄シートも `Judge_Results` も、1行目の `A1`〜`N1` はマクロが一切書き込みません。**
銘柄のメモ（決算日、上値のフシ、前日の傾向など）を自由に書いてください。
`Setup_All` を何度実行しても消えません。

> 例外として `S1:T1` と `W1:X1` だけは掃除します。旧版がここに RSS 数式を
> 置いていたため、残しておくと無駄な配信を掴み続けるからです。
> メモは `A1`〜`N1` に書いてください。

見出しは1〜2行目で固定してあるので、下にスクロールしてもメモと見出しは常に見えます。

## 2. 歩み値（TICK）ブロックの設定

「① 準備」を押すと各銘柄シートの `AA` 列に設定メモが出ます。
そこの指示どおり `RssTickList` を登録してください。

### いちばん簡単な方法：ボタン1つ

`Judge_Results` の **「歩み値の数式を全シートに設定」** ボタンを押すと、
**全銘柄シートに一括で** `RssTickList` が設定されます。銘柄シートを増やしたときも同じです。

書き込まれる内容:

```
AB5:AD5 : 時刻 / 出来高 / 約定値          ← 取得項目の見出し
AB4     : =RssTickList($AB$5:$AD$5,$B$3,300)
```

銘柄コードは各シートの `B3` を参照するので、シートごとに書き換える必要はありません。

押したあと数秒待って、**「歩み値ブロックの確認」** で読めているか確かめてください。

### 手で登録する場合

「Realtime Spread Sheet 投資情報」ダイアログで次のとおり設定します。

| 項目 | 設定値 |
|---|---|
| 関数指定 | **歩み値（RssTickList）** |
| 商品 | 国内株式 |
| 銘柄コード | **セル参照 → `B3`** |
| 表示本数 | **300**（最大。多いほど取りこぼしません） |
| 取得項目 | **時刻 / 出来高 / 約定値**（この順） |
| 表示開始セル | **`AB4`** ← ここを必ず変更 |

> ⚠ **表示開始セルを `B3` のままにしないでください。**
> `B3` は証券コードのセル、`D`〜`F` 列はティックログ領域です。
> `B3` を指定すると両方が歩み値に上書きされて壊れます。
>
> 既に `B3` で登録してしまった場合は、`B3` の数式を削除 → 証券コードを入れ直し →
> 「① 準備」をもう一度実行してください。

### 登録後のブロックの見た目

`RssTickList` は「表示開始セル」に**配信状態**、その**1行下に見出し**、
**2行下からデータ**（新しい順）を書き出します。

```
        AA                          AB              AC        AD
 1  歩み値（TICK）ブロック
 2  RssTickList をここに登録します
 3  　表示開始セル = AB3           =RssTickList(...) => 配信中   ← 配信状態
 4  　銘柄コード   = B3            時刻            出来高    約定値   ← RSSの見出し
 5  　表示本数     = 300           15:19:58        100       3130     ← データ（新しい順）
 6  　取得項目     = …             15:19:58        2400      3130
 7  ※見出しとデータは RSS が…      15:19:57        100       3129
```

**配信状態の行と見出しの行は自動で読み飛ばします**（時刻として解釈できない行は無視する作り）。
`表示開始セル` を `AB4` などにずらしても、そのまま動きます。

登録したら **「歩み値ブロックの確認」** ボタンで
「読めたティック数 / 最古 / 最新」が正しく出るか確認してください。

**並び順（新しい順／古い順）も自動判定**するので `TICK_BLOCK_ORDER` は触らなくて大丈夫です。

### 取得項目や本数を変えたとき

`Module_Config` の以下を合わせてください。

```vba
Public Const TICK_BLOCK_CELL  As String = "AB3"   ' 読み取り開始セル（配信状態の行を含む一番上）
Public Const TICK_BLOCK_ROWS  As Long   = 310     ' 表示本数300 + 状態行 + 見出し行 + 余裕
Public Const TB_OFF_TIME      As Long   = 0       ' 時刻
Public Const TB_OFF_VOL       As Long   = 1       ' 出来高
Public Const TB_OFF_PRICE     As Long   = 2       ' 約定値
Public Const TB_OFF_MARK      As Long   = -1      ' ティック記号（取得項目に加えたら 3 などに）
Public Const ANCHOR_DEPTH     As Long   = 3       ' 追従の位置合わせに使う本数
```

### 追従の位置合わせについて（`ANCHOR_DEPTH`）

引け際は `15:24:59 / 100 / 3130` のように **同一秒・同値・同数量のティックが連続**します。
直前1本だけを目印にすると位置を取り違えてティックを落とすため、
**直近3本の並び**で位置合わせしています。

重複の多いテープで検証したところ、1本だけだと最大 7.7% を取りこぼしましたが、
3本にすると 0.15% まで下がりました（二重計上はどちらも 0）。

### 設定前でも動きます

`LOG_MODE = 0`（既定）は記録開始時に歩み値ブロックを1回読み、ティックが読めれば
**歩み値追従**、読めなければ**出来高ポーリング**に自動で切り替わります。
どちらで動いたかは `Judge_Results` の状態欄に出ます。

| 時刻 | 操作 |
|---|---|
| 寄り前〜14:59 | ブックを開き、RSS にログイン済みにしておく |
| 14:5x | `自動開始を予約（14:59:30）` を1回押す（手動なら不要） |

## 3-2. 判定窓の決め方（`JUDGE_START` / `JUDGE_END`）

### 東証の時間割から来る制約

```
15:00 ─────────── ザラバ ───────────┐
                    15:22〜15:25 に大口が入りやすい
15:25:00  ザラバ終了 / クロージング・オークション開始（ティックは出ない）
15:30:00  板寄せ約定（1本で数百万株の巨大ティック）
```

- **ティックが出るのは 15:25:00 まで**。それ以降を窓に入れても増えません
- **15:30 の板寄せ約定は絶対に窓へ入れないこと**。1本で出来高が桁違いなので
  `Vol4` も `SpeedMax` も壊れます。`JUDGE_END > 15:25:00` は起動時に警告します

### 既定を 15:00〜15:24 にした理由

区間は判定窓を4等分するので、既定では **6分ずつ** になります。

| 窓 | 区間 | Vol4 が見る時間帯 | ②の成立 | 板寄せまでの余裕 |
|---|---|---|---|---|
| 15:00–15:20（旧） | 5分 | 15:15–15:20 | **×**（一番静かな時間帯） | 10分 |
| **15:00–15:24（既定）** | **6分** | **15:18–15:24** | **○** | **6分** |
| 15:04–15:24 | 5分 | 15:19–15:24 | ○（やや鋭い） | 6分 |
| 15:08–15:24 | 4分 | 15:20–15:24 | ○（最も鋭い） | 6分 |
| 15:05–15:25 | 5分 | 15:20–15:25 | ○（最も鋭い） | 5分 |

旧設定（15:00–15:20）は `Vol4` がザラバで一番静かな時間帯を見ていたため、
**②「終盤で大口集中」がほぼ成立せず、判定が中立に倒れやすい**状態でした。

窓を後ろにずらすほど②は鋭くなりますが、①の連続ティックを数えるサンプルが減り、
発注の余裕も削れます。既定の 15:00–15:24 はその折り合いです。

### 自分のデータで詰める

**「出来高プロファイル」** ボタンで、記録済みティックの**1分ごとの出来高・ティック数・構成比**が出ます。
判定窓の外も表示するので、「何分から大口が入るか」を自分の銘柄で確認して窓を決められます。

検証日は `JUDGE_END` を一時的に `15:25:00` にして記録すると、
15:20〜15:25 の伸びまで丸ごと見られます（発注はせず観測だけの日に）。

> 区間の境界は `Module_Config` を書き換えれば自動で追従します。
> `Vol1〜Vol4` のラベル（`15:00-06` など）も「① 準備」で自動生成されます。

## 4. 判定ロジック（実装内容）

### ① 方向判定（連続ティック）
- 15:00〜15:20 のティックを時系列で走査
- **ティック記号（↑↓）があればそれを使い**、無い行は前ティック比で判定
- 連続上昇回数の最大 `UpSeqMax`、連続下落回数の最大 `DnSeqMax` を取る
- 同値（→）は連続をリセット（`RESET_ON_FLAT = True`）

| 条件 | 判定 |
|---|---|
| `UpSeqMax >= 5` かつ `UpSeqMax > DnSeqMax` | 引け上方向（買い優勢） |
| `DnSeqMax >= 5` かつ `DnSeqMax > UpSeqMax` | 引け下方向（売り優勢） |
| それ以外 | 中立（板で最終確認） |

### ② 出来高初動判定（大口の本気）
- **判定窓を4等分**した区間ごとにティック出来高を合計 → `Vol1`〜`Vol4`
  （既定 15:00–15:24 なら 15:00-06 / 06-12 / 12-18 / 18-24 の6分ずつ）
- **`Vol4 > Vol3 × 1.5` かつ `Vol4 > Vol2` かつ `Vol4 > Vol1`** なら「終盤で大口集中＝引け方向確定」

### ③ 約定速度（Tick Speed）
- 同一秒内の約定回数をカウントし、最大値 `SpeedMax` を取る
- `SpeedMax >= 3` → **信頼度「高（アルゴ/大口）」**。板のノイズより①②を優先して読む材料になります
- 歩み値は約定1本ずつのデータなので、この値は**正確**です

### ④ 総合ジャッジ
| 判定 | 条件 |
|---|---|
| **買い** | ①が引け上方向 かつ ②Vol4優勢 |
| **売り** | ①が引け下方向 かつ ②Vol4優勢 |
| **中立** | 上記以外 → プレクロージングで板を見て最終判断 |

### 重み（G列）

出来高に応じて付与し、`BuyTotal` / `SellTotal`（中立時の参考スコア）に使います。

| 出来高 | 重み |
|---|---|
| 〜999 | 1 |
| 1,000〜4,999 | 2 |
| 5,000〜9,999 | 3 |
| 10,000〜 | 5 |

※ 出来高が空欄・0 の行だけは重み `0`（欠損データがスコアを汚さないようにするため）

`BuyTotal = 上昇ティックの重み合計 + 最良買気配の切り上げ回数`
`SellTotal = 下落ティックの重み合計 + 最良売気配の切り下げ回数`

### 最良気配

- 記録中（15:00〜15:20）は `Judge_Results` の **S:U 列**（最良買気配 / 最良売気配 / スプレッド）が **1秒ごとに更新**されます
- 歩み値には気配が含まれないため、ティック追記時に**そのときの最良気配をスタンプ**して J/K 列に残します
- 各銘柄シートの `S3:T6` にも 現在値 / 気配 / スプレッドのライブ表示があります
- 判定結果ブロックにも判定時点の 最良買気配 / 最良売気配 / スプレッド が入ります

## 5. シート構成

### 銘柄シート（`１` `2` `3` `4` …）

| セル / 列 | 内容 |
|---|---|
| 1行目 | **メモ欄**（A1〜N1。マクロは書き込みません） |
| B3 | 証券コード（**手入力するのはここだけ**） |
| C3 | `=RssMarket($B$3,"銘柄名称")` |
| D列 | 時刻（3行目からティックログ） |
| E列 | 出来高（ティック単体） |
| F列 | 約定値 |

> D〜F の並びは `RssTickList` の取得項目（時刻 / 出来高 / 約定値）に合わせています。
> 並べ替えたい場合は `Module_Config` の `COL_TIME` / `COL_VOL` / `COL_PRICE` を入れ替えれば
> 判定側は自動追従します（`IX_*` 定数が相対位置を計算します）。
| G列 | **重み**（1 / 2 / 3 / 5） |
| H列 | UpScore 累積（参考） |
| I列 | DnScore 累積（参考） |
| J列 | 最良買気配値（ティック時点） |
| K列 | 最良売気配値（ティック時点） |
| L列 | 方向（↑ / ↓ / →） |
| M列 | 同一秒内の約定連番（③の元データ） |
| N列 | ティック記号（RSS の歩み値そのまま） |
| O列 / P列 | 判定結果ブロック（2行目から18項目） |
| S列 / T列 | RSS ライブ表示（2行目から。現在値 / 出来高 / 気配 / 現在値時刻 / スプレッド） |
| AA列 | 歩み値ブロックの設定メモ |
| AB〜AD列 | 歩み値（TICK）ブロック（`AB3` に `RssTickList`） |

### `Judge_Results`

- `B2:U2` が見出し、3 行目から銘柄が並びます
- `D列（判定）` が **買い＝緑 / 売り＝赤 / 中立＝グレー**
- `S:U 列` が 最良買気配 / 最良売気配 / スプレッド（記録中もリアルタイム更新）
- `W2:X4` が状態表示、右側にボタンが 12 個

| ボタン | 動作 |
|---|---|
| ① 準備（表とRSSを作る） | 全シートの体裁・数式・ボタンを生成 |
| ② ティック記録 開始 | 15:00〜15:20 の歩み値追従を開始 |
| ③ 記録 停止 → 判定 | 記録を止めて判定 |
| ④ 判定 実行 | 記録済みログから再判定 |
| ⑤ ティックログ消去 | 全シートのログをクリア |
| 自動開始を予約（14:59:30） | `Application.OnTime` で自動起動 |
| 歩み値の数式を全シートに設定 | 全銘柄シートに `RssTickList` を一括設定 |
| 歩み値を今すぐ取込 | ブロックの内容を一括で取り込む（取りこぼし回収用） |
| 歩み値ブロックの確認 | 列の割り当てが合っているかの診断 |

## 6. パラメータ調整

`Module_Config` の先頭だけ触れば感度が変わります。

| 定数 | 既定 | 意味 |
|---|---|---|
| `JUDGE_START` / `JUDGE_END` | 15:00:00 / 15:24:00 | 判定対象時間帯（`JUDGE_END` は 15:25:00 以下） |
| `SEQ_MIN` | 5 | ①連続ティックの閾値 |
| `RESET_ON_FLAT` | True | 同値ティックで連続を切るか |
| `USE_TICK_MARK` | True | ①をティック記号（↑↓）で判定するか |
| `VOL_RATIO` | 1.5 | ②`Vol4 > Vol3 ×` この倍率 |
| `SPEED_MIN` | 3 | ③秒間約定数の閾値 |
| `LOG_MODE` | 0 | 0=自動判定 / 1=歩み値追従 / 2=出来高ポーリング |
| `POLL_MS` | 200 | ポーリング間隔（ミリ秒） |
| `TICK_BLOCK_*` | — | 歩み値ブロックの位置・行数・列割り当て |
| `AUTO_JUDGE_ON_STOP` | True | 15:20 に自動で判定まで走らせる |
| `AUTO_ARM_TIME` | 14:59:30 | 自動開始の予約時刻 |
| `AUTO_ARM_ON_OPEN` | True | ブックを開いたら自動で予約する |

### フォールバック（自動判定 / `LOG_MODE = 2`）

歩み値の数式が入っていない（または読めない）ときは、**現在値・出来高（当日累計）のポーリング**に
自動で切り替わります。
出来高の増分を1ティックとみなす方式で、`POLL_MS = 200` にすると1秒あたり最大5ティックまで分離できます。
ただしこの方式では `SpeedMax` の上限がポーリング間隔で決まってしまうので、
歩み値が取れるようになったら、そのまま何もしなくても自動で歩み値追従に切り替わります。

### CSV 取込（検証用）

```
時刻, 出来高, 約定値, 最良買気配値(任意), 最良売気配値(任意), ティック記号(任意)
15:00:03, 300, 2850, 2849, 2850, ↑
```

出来高が当日累計か単体かは取込時に選べます。

## 7. 元コードから直した点

| 箇所 | 問題 | 対応 |
|---|---|---|
| `sheetsArr = Array("1","2","3","4")` | シート名が **全角「１」** なのに半角「1」を指定。実行時エラー1352 で必ず落ちる | シート名をハードコードせず、`B3` にコードが入っているシートを自動検出（`TargetSheets`） |
| `Private Sub Workbook_Open()` が `Module1` にある | 標準モジュールの `Workbook_Open` は **呼ばれない**（そもそもブックを開くたび全判定を走らせるのは危険） | `ThisWorkbook` に移し、起動時は結果シートを開くだけに変更 |
| `WriteSummary` が `A3` 起点で書き込み | `Judge_Results` の見出しは `B2:F2`。**1列ずれる** | `B` 列起点に統一し、見出しも自動生成 |
| `Select Case vol` に `Case Else` なし | 出来高が空欄／0 のとき `w` が前の値のまま残り、スコアが汚れる | `VolWeight()` に切り出して `Case Else = 0` を追加 |
| `t = ws.Cells(i,"D").Value` を `Date` で受ける | 空欄・文字列で型不一致エラー | `TickSec()` で安全に秒へ変換、変換できない行はスキップ |
| ティックを取り込む処理が無い | シートに時刻・約定値・出来高が入らないので永久に判定できない | `Module_TickLogger`（歩み値ブロック追従）と `Module_Import`（CSV）を追加 |
| ①②③のロジックが未実装 | 実装は重み付きスコアのみ | `Module_Judge` に①〜④を実装。従来の重み付きスコアは「中立時の参考値」として存置 |
| 最良気配が使われていない | 見出しだけあって未使用 | ライブ表示・ティックへのスタンプ・気配スコア・判定結果への表示に使用 |
| `ws.Range("O1:O3")` に判定を直書き | `Judge_Results` の `O1:O3` に文字列が残ってレイアウトが崩れていた | 銘柄シートは `O列=ラベル / P列=値` に整理、残骸は準備時に掃除 |
