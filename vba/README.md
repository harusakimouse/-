# ティック判定ロジック（15:00〜15:20 専用）VBA 完成版

`Tik___V1.xlsm` を完成形にするための VBA 一式です。
15:20 に判定が出て、15:25 のプレクロージングに **買い / 売り / 中立** を持ち込める構成にしてあります。

```
15:00:00  ティック記録 開始   （ボタン② または 自動予約）
15:20:00  記録終了 → 自動で判定
15:20:03  Judge_Results に 買い / 売り / 中立 が並ぶ   ← ここを見て発注
15:25     プレクロージング（中立だけ板で最終判断）
15:30     板寄せ終了
```

---

## 1. 導入手順

1. `Tik___V1.xlsm` を開き、`Alt + F11` で VBE を開く
2. **既存の `Module1` を削除する**
   （右クリック →「Module1 の解放」→「エクスポートしますか？」はお好みで）
   *削除しないと `WriteSummary` が二重定義になり「名前が適切ではありません」で止まります*
3. 「ファイル」→「ファイルのインポート」で以下 5 本を取り込む
   - `Module_Config.bas`
   - `Module_Judge.bas`
   - `Module_TickLogger.bas`
   - `Module_Setup.bas`
   - `Module_Import.bas`
4. ツリーの `ThisWorkbook` をダブルクリックし、`ThisWorkbook_貼り付け用.txt` の中身を貼り付け
5. VBE で「デバッグ」→「VBAProject のコンパイル」がエラーなしなら OK
6. 各銘柄シートの **B3 に証券コード** を入れる（例: `7203`）
7. `Judge_Results` シートの **「① 準備（表とRSSを作る）」** を押す
   → 見出し・RSS 数式・判定結果ブロック・ボタンが自動生成されます
8. 上書き保存（マクロ有効ブック `.xlsm`）

## 2. 毎日の使い方

| 時刻 | 操作 |
|---|---|
| 寄り前〜14:59 | ブックを開き、RSS（マーケットスピード）にログイン済みにしておく |
| 14:5x | `自動開始を予約（14:59:30）` を1回押す（手動なら不要） |
| 15:00 | （自動）または `② ティック記録 開始` を押す |
| 15:00〜15:20 | 放置。`状態` 欄にティック件数が出続けます |
| 15:20 | 自動で記録終了 → 自動判定 → 一覧が色付きで出ます |
| 15:20〜15:25 | 買い＝赤緑の色で即判別。中立の行だけ板を見る |
| 15:25 | プレクロージングで発注 |

途中で止めたいときは `③ 記録 停止 → 判定`。
やり直すときは `⑤ ティックログ消去`。

## 3. 判定ロジック（実装内容）

### ① 方向判定（連続ティック）
- 15:00〜15:20 のティックを時系列で走査
- 前ティック比で上昇／下落を判定し、**連続上昇回数の最大 `UpSeqMax`**、**連続下落回数の最大 `DnSeqMax`** を取る
- 同値ティックは連続を **リセット**（`RESET_ON_FLAT = True`。緩めたいなら `False`）

| 条件 | 判定 |
|---|---|
| `UpSeqMax >= 5` かつ `UpSeqMax > DnSeqMax` | 引け上方向（買い優勢） |
| `DnSeqMax >= 5` かつ `DnSeqMax > UpSeqMax` | 引け下方向（売り優勢） |
| それ以外 | 中立（板で最終確認） |

### ② 出来高初動判定（大口の本気）
- 15:00-05 / 05-10 / 10-15 / 15-20 の4区間に分け、ティック出来高を合計 → `Vol1`〜`Vol4`
- **`Vol4 > Vol3 × 1.5` かつ `Vol4 > Vol2` かつ `Vol4 > Vol1`** なら「終盤で大口集中＝引け方向確定」

### ③ 約定速度（Tick Speed）
- 同一秒内の約定回数をカウントし、最大値 `SpeedMax` を取る
- `SpeedMax >= 3` → アルゴ／大口が本気。**信頼度「高（アルゴ/大口）」** として表示し、板のノイズより①②を優先して読む材料にします

### ④ 総合ジャッジ
| 判定 | 条件 |
|---|---|
| **買い** | ①が引け上方向 かつ ②Vol4優勢 |
| **売り** | ①が引け下方向 かつ ②Vol4優勢 |
| **中立** | 上記以外 → プレクロージングで板を見て最終判断 |

中立のときの参考値として、既存の重み付きスコア（`BuyTotal` / `SellTotal`）も併記します。
`重み` は出来高で 1 / 2 / 3 / 5、これに気配の切り上げ・切り下げ回数を足したものです。

## 5. パラメータ調整

`Module_Config` の先頭だけ触れば感度が変わります。

| 定数 | 既定 | 意味 |
|---|---|---|
| `JUDGE_START` / `JUDGE_END` | 15:00:00 / 15:20:00 | 判定対象時間帯 |
| `SEQ_MIN` | 5 | ①連続ティックの閾値 |
| `RESET_ON_FLAT` | True | 同値ティックで連続を切るか |

| `SPEED_MIN` | 3 | ③秒間約定数の閾値 |
| `POLL_MS` | 200 | RSS ポーリング間隔（ミリ秒） |
| `AUTO_JUDGE_ON_STOP` | True | 15:20 に自動で判定まで走らせる |
| `AUTO_ARM_TIME` | 14:59:30 | 自動開始の予約時刻 |
| `USE_RSS_TIME` | True | 時刻を RSS の「現在値時刻」から取る |

## 6. ティックの取り込み方式について

RSS は歩み値そのものを配信しないため、**現在値・出来高（当日累計）を高速ポーリングし、
出来高が増えた瞬間を1ティックとして記録**しています。

```
ティック出来高 = 今回の累計出来高 − 前回の累計出来高
```

- `POLL_MS = 200`（既定）で **1秒あたり最大5ティック**まで分離できるので、`SpeedMax >= 3` の判定が成立します
- 重い場合は 250〜500 に上げてください。そのぶん `SpeedMax` の分解能は落ちます
- 同一 200ms 内に複数約定があった場合は1ティックにまとまります（出来高は合算されるので②は影響なし、③だけ控えめに出ます）

**歩み値 CSV がある場合**は `CSV（歩み値）取込` ボタンから読み込めます。
この場合は約定1本ずつのデータなので `SpeedMax` が正確に出ます。

CSV の列並び（1行目が見出しでも可）:

```
時刻, 約定値, 出来高, 最良買気配値(任意), 最良売気配値(任意)
15:00:03, 2850, 300, 2849, 2850
```

出来高が当日累計か単体かは取込時に選べます。

## 7. 元コードから直した点

| 箇所 | 問題 | 対応 |
|---|---|---|
| `sheetsArr = Array("1","2","3","4")` | シート名が **全角「１」** なのに半角「1」を指定。実行時エラー1352 で必ず落ちる | シート名をハードコードせず、`B3` にコードが入っているシートを自動検出（`TargetSheets`） |
| `Private Sub Workbook_Open()` が `Module1` にある | 標準モジュールの `Workbook_Open` は **呼ばれない**（そもそもブックを開くたび全判定を走らせるのは危険） | `ThisWorkbook` に移し、起動時は結果シートを開くだけに変更 |
| `WriteSummary` が `A3` 起点で書き込み | `Judge_Results` の見出しは `B2:F2`。**1列ずれる** | `B` 列起点に統一し、見出しも自動生成 |
| `Select Case vol` に `Case Else` なし | 出来高が空欄／0 のとき `w` が前の値のまま残り、スコアが汚れる | `VolWeight()` に切り出して `Case Else = 0` を追加 |
| `t = ws.Cells(i,"D").Value` を `Date` で受ける | 空欄・文字列で型不一致エラー | `TickSec()` で安全に秒へ変換、変換できない行はスキップ |
| ティックを取り込む処理が無い | シートに時刻・約定値・出来高が入らないので永久に判定できない | `Module_TickLogger`（RSS高速ポーリング）と `Module_Import`（CSV）を追加 |
| ①②③のロジックが未実装 | 実装は重み付きスコアのみ | `Module_Judge` に①連続ティック／②4区間出来高／③秒間約定速度／④総合ジャッジを実装。従来の重み付きスコアは「中立時の参考値」として存置 |
| `ws.Range("O1:O3")` に判定を直書き | `Judge_Results` の `O1:O3` に文字列が残ってレイアウトが崩れていた | 銘柄シートは `O列=ラベル / P列=値` に整理、`Judge_Results` の残骸は準備時に掃除 |

## 8. 注意

- 判定結果は **発注はしません**。買い／売りのフラグを出すところまでです
- 記録中はマクロがループしているため、他ブックでの重い操作は避けてください（`DoEvents` を回しているので Excel の操作自体は可能です）
- 一日信用の建玉・返済は従来どおり手動 or 別ブック側で行ってください
