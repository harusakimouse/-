# ティック判定ロジック（15:00〜15:20 専用）VBA 完成版

`Tik___V1.xlsm` を完成形にするための VBA 一式です。
RSS の**歩み値（TICK）**を追従して記録し、15:20 に **買い / 売り / 中立** を出して 15:25 のプレクロージングに持ち込みます。

```
15:00:00  歩み値の記録 開始   （ボタン② または 自動予約）
15:00〜   Judge_Results に 最良買気配 / 最良売気配 / スプレッド をリアルタイム表示
15:20:00  記録終了 → 自動で判定
15:20:03  買い / 売り / 中立 が色分けで並ぶ   ← ここを見て発注
15:25     プレクロージング（中立だけ板で最終判断）
15:30     板寄せ終了
```

---

## 1. 導入手順

1. `Tik___V1.xlsm` を開き、`Alt + F11` で VBE を開く
2. **既存の `Module1` を削除する**
   （右クリック →「Module1 の解放」）
   *削除しないと `WriteSummary` が二重定義になり「名前が適切ではありません」で止まります*
3. 「ファイル」→「ファイルのインポート」で以下 5 本を取り込む
   - `Module_Config.bas`
   - `Module_Judge.bas`
   - `Module_TickLogger.bas`
   - `Module_Setup.bas`
   - `Module_Import.bas`
4. ツリーの `ThisWorkbook` をダブルクリックし、`ThisWorkbook_貼り付け用.txt` の中身を貼り付け
5. VBE で「デバッグ」→「VBAProject のコンパイル」がエラーなしなら OK
6. 各銘柄シートの **B3 に証券コード** を入れる（例: `7203`）
7. `Judge_Results` の **「① 準備（表とRSSを作る）」** を押す
8. **各銘柄シートの `AB3` に、お使いの RSS の歩み値数式を入れる**（← 重要。次章）
9. `Judge_Results` の **「歩み値ブロックの確認」** を押して読めているか確認
10. 上書き保存（マクロ有効ブック `.xlsm`）

## 2. 歩み値（TICK）ブロックの設定  ← ここだけ環境依存

歩み値の関数名・引数はご利用の RSS によって違うので、**数式そのものは貼っていません**。
「① 準備」を押すと各銘柄シートの `AA〜AE` 列に置き場所だけ用意されるので、
`AB3` にお使いの RSS の歩み値数式を入れてください。

```
        AA              AB        AC       AD       AE
 1  歩み値（TICK）ブロック
 2  → AB3 に数式を…    時刻      約定値   出来高   ティック
 3                      ←ここに歩み値のRSS数式
 …                      （300行ぶん流れてくる想定）
```

期待する列並びは **時刻 / 約定値 / 出来高 / ティック記号(↑↓)** の4列です。
違う並びなら `Module_Config` の下記だけ直せば合います。

```vba
Public Const TICK_BLOCK_CELL  As String = "AB3"   ' ブロックの左上セル
Public Const TICK_BLOCK_ROWS  As Long   = 300     ' 読み取る行数
Public Const TB_OFF_TIME      As Long   = 0       ' 時刻の列オフセット
Public Const TB_OFF_PRICE     As Long   = 1       ' 約定値
Public Const TB_OFF_VOL       As Long   = 2       ' 出来高
Public Const TB_OFF_MARK      As Long   = 3       ' ティック記号（無ければ -1）
Public Const TICK_BLOCK_ORDER As Long   = 0       ' 0=自動判定 1=新しい順 2=古い順
```

**並び順（新しい順／古い順）は自動判定**するので、通常は触らなくて大丈夫です。
`歩み値ブロックの確認` ボタンで「読めたティック数 / 最古 / 最新」が出るので、
そこが正しければ設定は合っています。

### 追従のしくみ

毎ポーリングでブロック全体を読み、**前回の最終ティックがブロックのどこにあるか**を探して、
それより新しい行だけを追記します。したがって

- 同じティックが二重に記録されることはありません
- 途中で記録を止めて再開しても、続きから記録されます
- ブロックを一周されてしまった（＝取りこぼした）場合は警告を出します
  → `TICK_BLOCK_ROWS` を増やすか `POLL_MS` を短くしてください

既定（300行 / 300ms）なら 1秒あたり 1000ティック以上こないと取りこぼしません。

## 3. 毎日の使い方

| 時刻 | 操作 |
|---|---|
| 寄り前〜14:59 | ブックを開き、RSS にログイン済みにしておく |
| 14:5x | `自動開始を予約（14:59:30）` を1回押す（手動なら不要） |
| 15:00 | （自動）または `② ティック記録 開始` |
| 15:00〜15:20 | 放置。ティック件数と**最良気配**が1秒ごとに更新されます |
| 15:20 | 自動で記録終了 → 自動判定 → 一覧が色付きで出ます |
| 15:20〜15:25 | 買い＝緑 / 売り＝赤 で即判別。中立の行だけ気配とスプレッドを見る |
| 15:25 | プレクロージングで発注 |

途中で止めたいときは `③ 記録 停止 → 判定`。やり直すときは `⑤ ティックログ消去`。

## 4. 判定ロジック（実装内容）

### ① 方向判定（連続ティック）
- 15:00〜15:20 のティックを時系列で走査
- **ティック記号（↑↓）があればそれを使い**、無い行は前ティック比で判定
- 連続上昇回数の最大 `UpSeqMax`、連続下落回数の最大 `DnSeqMax` を取る
- 同値（→）は連続をリセット（`RESET_ON_FLAT = True`）

| 条件 | 判定 |
|---|---|
| `UpSeqMax >= 5` かつ `UpSeqMax > DnSeqMax` | 引け上方向（買い優勢） |
| `DnSeqMax >= 5` かつ `DnSeqMax > UpSeqMax` | 引け下方向（売り優勢） |
| それ以外 | 中立（板で最終確認） |

### ② 出来高初動判定（大口の本気）
- 15:00-05 / 05-10 / 10-15 / 15-20 の4区間に分け、ティック出来高を合計 → `Vol1`〜`Vol4`
- **`Vol4 > Vol3 × 1.5` かつ `Vol4 > Vol2` かつ `Vol4 > Vol1`** なら「終盤で大口集中＝引け方向確定」

### ③ 約定速度（Tick Speed）
- 同一秒内の約定回数をカウントし、最大値 `SpeedMax` を取る
- `SpeedMax >= 3` → **信頼度「高（アルゴ/大口）」**。板のノイズより①②を優先して読む材料になります
- 歩み値は約定1本ずつのデータなので、この値は**正確**です

### ④ 総合ジャッジ
| 判定 | 条件 |
|---|---|
| **買い** | ①が引け上方向 かつ ②Vol4優勢 |
| **売り** | ①が引け下方向 かつ ②Vol4優勢 |
| **中立** | 上記以外 → プレクロージングで板を見て最終判断 |

### 重み（G列）

出来高に応じて付与し、`BuyTotal` / `SellTotal`（中立時の参考スコア）に使います。

| 出来高 | 重み |
|---|---|
| 〜999 | 1 |
| 1,000〜4,999 | 2 |
| 5,000〜9,999 | 3 |
| 10,000〜 | 5 |

※ 出来高が空欄・0 の行だけは重み `0`（欠損データがスコアを汚さないようにするため）

`BuyTotal = 上昇ティックの重み合計 + 最良買気配の切り上げ回数`
`SellTotal = 下落ティックの重み合計 + 最良売気配の切り下げ回数`

### 最良気配

- 記録中（15:00〜15:20）は `Judge_Results` の **S:U 列**（最良買気配 / 最良売気配 / スプレッド）が **1秒ごとに更新**されます
- 歩み値には気配が含まれないため、ティック追記時に**そのときの最良気配をスタンプ**して J/K 列に残します
- 各銘柄シートの `S3:T6` にも 現在値 / 気配 / スプレッドのライブ表示があります
- 判定結果ブロックにも判定時点の 最良買気配 / 最良売気配 / スプレッド が入ります

## 5. シート構成

### 銘柄シート（`１` `2` `3` `4` …）

| セル / 列 | 内容 |
|---|---|
| B3 | 証券コード（**手入力するのはここだけ**） |
| C3 | `=RssMarket($B$3,"銘柄名称")` |
| D列 | 時刻（3行目からティックログ） |
| E列 | 約定値 |
| F列 | 出来高（ティック単体） |
| G列 | **重み**（1 / 2 / 3 / 5） |
| H列 | UpScore 累積（参考） |
| I列 | DnScore 累積（参考） |
| J列 | 最良買気配値（ティック時点） |
| K列 | 最良売気配値（ティック時点） |
| L列 | 方向（↑ / ↓ / →） |
| M列 | 同一秒内の約定連番（③の元データ） |
| N列 | ティック記号（RSS の歩み値そのまま） |
| O列 / P列 | 判定結果ブロック（判定・最良気配・Vol1〜4・SpeedMax など18項目） |
| S列 / T列 | RSS ライブ表示（現在値 / 出来高 / 最良買気配 / 最良売気配 / 現在値時刻 / スプレッド） |
| AA〜AE列 | 歩み値（TICK）ブロック |

### `Judge_Results`

- `B2:U2` が見出し、3 行目から銘柄が並びます
- `D列（判定）` が **買い＝緑 / 売り＝赤 / 中立＝グレー**
- `S:U 列` が 最良買気配 / 最良売気配 / スプレッド（記録中もリアルタイム更新）
- `W1:X3` が状態表示、右側にボタンが 10 個

| ボタン | 動作 |
|---|---|
| ① 準備（表とRSSを作る） | 全シートの体裁・数式・ボタンを生成 |
| ② ティック記録 開始 | 15:00〜15:20 の歩み値追従を開始 |
| ③ 記録 停止 → 判定 | 記録を止めて判定 |
| ④ 判定 実行 | 記録済みログから再判定 |
| ⑤ ティックログ消去 | 全シートのログをクリア |
| 自動開始を予約（14:59:30） | `Application.OnTime` で自動起動 |
| 歩み値を今すぐ取込 | ブロックの内容を一括で取り込む（取りこぼし回収用） |
| 歩み値ブロックの確認 | 列の割り当てが合っているかの診断 |
| CSV（歩み値）取込 | 検証・バックテスト用 |
| 銘柄シートを追加 | コードを聞いて新規シートを生成 |

## 6. パラメータ調整

`Module_Config` の先頭だけ触れば感度が変わります。

| 定数 | 既定 | 意味 |
|---|---|---|
| `JUDGE_START` / `JUDGE_END` | 15:00:00 / 15:20:00 | 判定対象時間帯 |
| `SEQ_MIN` | 5 | ①連続ティックの閾値 |
| `RESET_ON_FLAT` | True | 同値ティックで連続を切るか |
| `USE_TICK_MARK` | True | ①をティック記号（↑↓）で判定するか |
| `VOL_RATIO` | 1.5 | ②`Vol4 > Vol3 ×` この倍率 |
| `SPEED_MIN` | 3 | ③秒間約定数の閾値 |
| `LOG_MODE` | 1 | 1=歩み値追従 / 2=出来高ポーリング |
| `POLL_MS` | 300 | ポーリング間隔（ミリ秒） |
| `TICK_BLOCK_*` | — | 歩み値ブロックの位置・行数・列割り当て |
| `AUTO_JUDGE_ON_STOP` | True | 15:20 に自動で判定まで走らせる |
| `AUTO_ARM_TIME` | 14:59:30 | 自動開始の予約時刻 |

### フォールバック（`LOG_MODE = 2`）

歩み値が使えない環境向けに、**現在値・出来高（当日累計）のポーリング**モードも残してあります。
出来高の増分を1ティックとみなす方式で、`POLL_MS = 200` にすると1秒あたり最大5ティックまで分離できます。
ただしこの方式では `SpeedMax` の上限がポーリング間隔で決まってしまうので、
歩み値が取れるなら `LOG_MODE = 1` のままにしてください。

### CSV 取込（検証用）

```
時刻, 約定値, 出来高, 最良買気配値(任意), 最良売気配値(任意), ティック記号(任意)
15:00:03, 2850, 300, 2849, 2850, ↑
```

出来高が当日累計か単体かは取込時に選べます。

## 7. 元コードから直した点

| 箇所 | 問題 | 対応 |
|---|---|---|
| `sheetsArr = Array("1","2","3","4")` | シート名が **全角「１」** なのに半角「1」を指定。実行時エラー1352 で必ず落ちる | シート名をハードコードせず、`B3` にコードが入っているシートを自動検出（`TargetSheets`） |
| `Private Sub Workbook_Open()` が `Module1` にある | 標準モジュールの `Workbook_Open` は **呼ばれない**（そもそもブックを開くたび全判定を走らせるのは危険） | `ThisWorkbook` に移し、起動時は結果シートを開くだけに変更 |
| `WriteSummary` が `A3` 起点で書き込み | `Judge_Results` の見出しは `B2:F2`。**1列ずれる** | `B` 列起点に統一し、見出しも自動生成 |
| `Select Case vol` に `Case Else` なし | 出来高が空欄／0 のとき `w` が前の値のまま残り、スコアが汚れる | `VolWeight()` に切り出して `Case Else = 0` を追加 |
| `t = ws.Cells(i,"D").Value` を `Date` で受ける | 空欄・文字列で型不一致エラー | `TickSec()` で安全に秒へ変換、変換できない行はスキップ |
| ティックを取り込む処理が無い | シートに時刻・約定値・出来高が入らないので永久に判定できない | `Module_TickLogger`（歩み値ブロック追従）と `Module_Import`（CSV）を追加 |
| ①②③のロジックが未実装 | 実装は重み付きスコアのみ | `Module_Judge` に①〜④を実装。従来の重み付きスコアは「中立時の参考値」として存置 |
| 最良気配が使われていない | 見出しだけあって未使用 | ライブ表示・ティックへのスタンプ・気配スコア・判定結果への表示に使用 |
| `ws.Range("O1:O3")` に判定を直書き | `Judge_Results` の `O1:O3` に文字列が残ってレイアウトが崩れていた | 銘柄シートは `O列=ラベル / P列=値` に整理、残骸は準備時に掃除 |

## 8. 注意

- 判定結果は **発注はしません**。買い／売りのフラグを出すところまでです
- 記録中はマクロがループしていますが `DoEvents` を回しているので Excel の操作は可能です
- 一日信用の建玉・返済は従来どおり手動 or 別ブック側で行ってください
