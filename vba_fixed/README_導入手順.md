# Tik 大引V1.xlsm — 修正版 VBA 一式

2026-08-31 の「記録 0 件」調査で見つかった不具合 16 件を全部直したソースです。
そのまま VBE にインポートすれば入れ替わります。

---

## 0. なぜ .xlsm ではなくソースで渡すのか

`vbaProject.bin`（VBA の格納形式）は独自のバイナリ圧縮で、Excel を使わずに
安全に書き戻す手段がありません。壊れたブックを渡すより、テキストで渡して
VBE の標準機能でインポートしてもらうほうが確実です。作業は 3 分ほどです。

---

## 1. 文字化け対策（重要）

VBE の「ファイルのインポート」は、ファイルを **ANSI（日本語 Windows では
Shift-JIS / CP932）** として読みます。UTF-8 の `.bas` をインポートすると、
コメントも文字列も全部文字化けします。判定文言（`"買い"` `"売り"` など）まで
壊れるので、**動作にも影響します。**

そのため 2 種類を用意しました。**インポートに使うのは `ShiftJIS/` のほうです。**

| フォルダ | 文字コード | 改行 | 用途 |
|---|---|---|---|
| `vba_fixed/ShiftJIS/` | **CP932（Shift-JIS）・BOM なし** | CRLF | **VBE へのインポート用。こちらを使う** |
| `vba_fixed/` | UTF-8 | LF | Git 差分の閲覧・GitHub 上での参照用 |

中身は同一です（CP932 で往復変換して一致を確認済み）。CP932 で表現できない
文字は使っていません（`⚠` を含んでいたので `【警告】` に置き換えました）。

**確実な代替手段**：VBE に**コピー＆ペースト**する分にはクリップボードが
Unicode なので、どちらのファイルからでも文字化けしません。インポートで
少しでも崩れたら、モジュールを空にしてから貼り付け直してください。

インポート後に化けていないかは、`Module_Config` の先頭コメント
「共通設定・共通関数・共通型」が読めるかどうかで一目で分かります。

## 3. インポート手順

1. `Tik 大引V1.xlsm` を開く（マクロ有効）。
   開いた直後に自動開始が予約されるので、ザラバ中なら先に
   **「③ 記録 停止 → 判定」** を一度押して止めておくと安全です。

2. `Alt` + `F11` で VBE を開く。

3. プロジェクトエクスプローラで、**標準モジュール 5 つを削除**する。
   （右クリック →「〜の解放」→「削除しますか？」に **いいえ**）

   - `Module_Config`
   - `Module_TickLogger`
   - `Module_Judge`
   - `Module_Setup`
   - `Module_Import`

   ※ `ThisWorkbook` と `Sheet〜` は削除できません（このあと 5 で中身を差し替えます）。

4. メニュー **ファイル → ファイルのインポート** で、**`ShiftJIS/` フォルダの**
   次の 7 つを 1 つずつ取り込む。

   - `Module_Config.bas`
   - `Module_TickLogger.bas`
   - `Module_Judge.bas`
   - `Module_Setup.bas`
   - `Module_Import.bas`
   - `Module_Diag.bas` ← **新規**（RSS 疎通テストと設定点検）
   - `Module_Help.bas` ← **新規**（「手順書」「表の見方」シートの生成）

5. `ThisWorkbook` をダブルクリックし、中身を全選択して削除。
   `ShiftJIS/ThisWorkbook.cls` をテキストエディタで開き、
   **`Option Explicit` の行から下だけ**をコピーして貼り付ける。
   （先頭の `VERSION 1.0 CLASS` 〜 `Attribute VB_Exposed = True` は
   インポート用のヘッダなので、貼り付けないでください）

6. メニュー **デバッグ → VBAProject のコンパイル** を実行。
   エラーが出なければ完了です。

7. `Ctrl` + `S` で保存。

## 4. インポート後にやること

順番どおりに。

1. **「設定の点検」ボタン**（新規）を押す。
   判定窓・パラメータ・各シートの歩み値の鮮度が一覧で出ます。
   「要確認」に何も出なければ設定は健全です。

2. **「① 準備（表とRSSを作る）」** を押す。
   Judge_Results に実行ログ欄（Y:Z 列）と新ボタン 2 つが追加されます。
   歩み値の数式が入っていないシートがあれば、その場で設定するか聞いてきます。

3. **銘柄コードの重複を直す**（下の「手作業が必要な 1 件」を参照）。

4. ザラバ中に **「★ RSS 疎通テスト（切り分け）」** を押す。
   約 20 秒で、8/31 の停止がループのせいだったのか RSS 側だったのかが出ます。

## 5. 手作業が必要な 1 件

**シート「2」「3」「4」の `B3` がすべて 6758（ソニーグループ）になっています。**

狙いの銘柄コードに書き換えてから「① 準備」を押し直してください。
修正版は重複を見つけると準備時と記録開始時に警告を出しますが、
どの銘柄を入れたいかは判断できないので、ここだけは手で直す必要があります。

## 6. 新しく増えたボタン

| ボタン | 何をするか |
|---|---|
| ★ RSS 疎通テスト（切り分け） | アイドル 10 秒 → ループ占有 10 秒 で配信を観測し、「ループが RSS を締め出している」「配信が来ていない」「ループは無関係」を自動判定します |
| 設定の点検 | 判定窓・パラメータ・各シートの歩み値の鮮度・設定の矛盾を一覧表示します |
| 手順書・表の見方を作り直す | 説明シート 2 枚を作り直します |

ボタンの定義は `Module_Setup.ButtonTable()` に 1 か所だけ書いてあります。
ボタンの作成も「手順書」シートのボタン一覧もここから生成するので、
ボタンを足しても説明がずれません。

「② ティック記録 開始」の割り当て先が `StartTickLogging` から
`StartTickLoggingButton` に変わっています（自動起動のときだけダイアログを
出さないようにするため）。「① 準備」を押せばボタンは作り直されます。

---

## 7. 増えたシート

「① 準備」を押すと、**無ければ**次の 2 枚が作られます（既にあれば触りません）。
どちらも B3 に証券コードが入らないので、判定対象の銘柄シートにはなりません。

| シート | 内容 |
|---|---|
| **手順書** | 毎日の運用手順、朝の確認、銘柄の変え方、症状別の対処、ボタン一覧、触ってはいけない場所 |
| **表の見方** | 判定の決まり方、①②③の中身、Judge_Results と銘柄シートの全列の意味、色の意味、数字を読むときの注意 |

作り直したいときは「手順書・表の見方を作り直す」ボタン。
どちらのシートも 1 行目は自由メモ欄で、作り直しても消えません。

判定窓やパラメータを変えると、説明の中の数字（`15:00:00`〜`15:24:00`、
`SEQ_MIN = 5` など）も定数から自動生成されるので、作り直せば追従します。

## 8. Judge_Results に増えた表示

ボタンの右側（Y:Z 列）に**実行ログ**が出ます。状態セル（X2）は判定完了で
上書きされてしまうため、あとから検証できるよう別枠にしました。

| セル | 内容 |
|---|---|
| Z2 | 記録の開始時刻 |
| Z3 | 取込モード（歩み値追従 / 出来高ポーリング）と切替の履歴 |
| Z4 | 配信状態（歩み値の最新時刻が何秒前か、RssTickList の戻り値） |
| Z5 | 最終ティック |
| Z6 | 警告（配信停止・取りこぼし・重複コードなど） |
| Z7 | 記録の終了時刻 |

AA 列（AA2:AA4）は `Application.OnTime` の予約時刻を保存する内部管理用です。
**消さないでください。** VBA の状態がリセットされても、ここから予約を
確実に解除するために使います。

## 9. 直した内容

| # | 不具合 | 直し方 |
|---|---|---|
| F-01 | 25 分間の VBA ループが Excel を占有し RSS を締め出す | `Application.OnTime` による 1 秒ごとの再スケジュールに変更。1 回ぶんの取込が終わるとマクロが完全に終了し、Excel が空きます |
| F-02 | 配信が止まっても検知しない | 開始時に配信状態と鮮度をチェック。記録中も `STALE_LIMIT_SEC`（60 秒）ティックが無ければ状態セルを黄色にして警告。判定側もティック 0 件を「中立」ではなく **「未計測」** と表示 |
| F-03 | RSS の現在値時刻が秒なしで ③SpeedMax が壊れる | `USE_RSS_TIME` を既定 False に。True にしても `"14:33"` のような秒なしを検出したら PC 時計に自動で切り替えて警告します |
| F-04 | 銘柄コードの重複 | `DuplicateCodeWarning()` を追加し、準備時・記録開始時・設定点検で警告（コード自体の修正は手作業） |
| F-05 | 取込モードの判定が開始時 1 回きり | 「読めるか」ではなく「60 秒以内に更新されているか」で判定。まだ 1 件も取れていない間はポーリングごとに見直して切り替えます |
| F-06 | アンカー探索が後ろ向きで取りこぼす | 位置合わせを「最後に取り込んだ秒＋その秒の取込本数」に変更。値の一致で探さないので、同一秒・同値・同数量が連続しても取りこぼしも二重取込も起きません |
| F-07 | 毎ポーリングの処理量が過大 | 300 行ぶんのキー文字列生成を全廃。ポーリング間隔も 200ms → 1 秒に |
| F-08 | 1 ティックごとに 5 回のセル書き込み＋書式設定 | 1 サイクルぶんを配列にためて 3 回の一括書き込みに。行ごとの `NumberFormatLocal` は削除（列単位で設定済み）。判定処理は `xlCalculationManual` で囲み、`Fin:` で必ず戻します（**記録中は手動にしません** — RTD が反映されなくなるため） |
| F-09 | 記録中に他のボタンが押せて壊れる | `BlockedWhileLogging()` を追加し、準備・消去・取込・判定・CSV・シート追加をブロック。`Workbook_BeforeClose` は判定を走らせずに停止 |
| F-10 | OnTime 予約が解除できなくなる | 予約時刻を Judge_Results の AA3/AA4 に保存し、そこから解除。ブックを開いた直後にも前回の残骸を解除します |
| F-11 | 並び順の自動判定が誤る | `TICK_BLOCK_ORDER = 1`（新しい順）に固定 |
| F-12 | ブロック読み取り位置が 1 行ずれ | `TICK_BLOCK_CELL = "AB4"`（= `TICK_FORMULA_CELL`）に統一し、`TICK_BLOCK_ROWS` は `TICK_SHOW_ROWS + 8` から自動算出。ずれていたら `LayoutWarning()` が知らせます |
| F-13 | `USE_TICK_MARK` が実質無効 | `TB_OFF_MARK >= 0` のときだけ有効に。無効時は N 列への空文字書き込みも停止。`ApplyTickFormula` は取得項目を 3/4 個で自動生成 |
| F-14 | 開始時刻とモードが判定完了で消える | 実行ログ（Y:Z 列）に分離 |
| F-15 | `ClearAllTicks` が気配列を消し残す | 消去範囲を `SUM_COL_FIRST`〜`SUM_COL_LAST`（B:U）に統一。実行ログも消去 |
| F-16 | コメントと定数の食い違い | 全モジュールのコメントを実際の定数に合わせて書き直し。`Setup_All` は歩み値の数式が無ければその場で設定を促します |

ほかに、調査中に見つかった小さな不具合も直しています。

- `Application.OnTime` のマクロ名をブック名で修飾（`'Tik 大引V1.xlsm'!PollTick`）。
  ブック名に空白があるため、別ブックがアクティブなときに解決に失敗する余地がありました。
- `JudgeAll` の `Fin:` で、`On Error Resume Next` が `Err` をクリアしてしまい
  エラーを検知できなくなる箇所を修正（先に退避）。
- CSV 取込で、`Open` に失敗した場合に未オープンのファイルを `Close` していた箇所を修正。
