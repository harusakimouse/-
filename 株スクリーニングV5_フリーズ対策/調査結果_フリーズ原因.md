# 株スクリーニング V5 フリーズ原因 調査結果

対象ファイル: `株スクリーニング_V5.xlsm`（VBAプロジェクト全5モジュール / 約3,000行を全読み）

---

## 結論（原因は4つ。順番に効きます）

| # | 原因 | 効き目 |
|---|---|---|
| **1** | **元データブックを「自動計算」のまま開いている** | ★★★★★ |
| **2** | 約定確認のダイアログが画面停止中に裏側で出る | ★★★★ |
| **3** | 更新処理に `DoEvents` が1つも無い（Windowsが「応答なし」判定） | ★★★ |
| **4** | 出力をセル1個ずつ書いている＋毎回 AutoFit | ★★ |

**計算量の問題ではありません。** 診断シートを見ると母集団は **301銘柄 / 250営業日** だけです。
この規模なら計算そのものは数秒で終わります。止まっているのは計算ではなく **Excelの再計算と画面まわり** です。

---

## 1. 元データブックを自動計算のまま開いている（本命）

VBA全体を検索しましたが、**`Application.Calculation = xlCalculationManual` が1か所もありません。**

- `Mod_S2_Screen` の `S2_Core`
  → `oldCalc = Application.Calculation` で**値を控えているだけ**。手動に切り替えていない。
- `Mod_S2_Rules` の `S2_バックテスト`
  → Calculation を**控えてすらいない**。

その状態で `Mod_S2_Data` の `S2_OpenSrc` が

```vba
Set wb = Application.Workbooks.Open(Filename:=p, UpdateLinks:=0, ReadOnly:=True)
```

を実行します。設定シートの元ブックは

```
C:\Users\Abe Hideaki\Desktop\OHLCV　明日売買　ボリンジャー送信.xlsm
```

**ボリンジャー計算の数式が入った重いブック**です。自動計算のまま開くと、Excelは
このブックの全数式を先に計算し終えるまで戻ってきません。VBAはその1行で待たされ、
Excelは操作不能（＝フリーズ）になります。

さらに元ブックに **RSS（楽天RSS / マーケットスピード等）の関数が入っていると、
値が返るまで永久に待ちます。**この場合は「何分待っても終わらない」形で固まります。

### 30秒でできる確認方法
1. Excelを新規で開く → 数式タブ → 計算方法を **「手動」** にする
2. その状態で `OHLCV　明日売買　ボリンジャー送信.xlsm` を手で開く
3. **すぐ開けばこれが原因で確定**（自動計算だと固まるはず）

---

## 2. 約定確認のダイアログが「裏」に出る

`S2_Core` は最初に `Application.ScreenUpdating = False`（画面を止める）にします。
その **止めたまま** `S2_ConfirmFills` が注文1件ごとに `MsgBox` を出します。

- 画面が更新されないので、ダイアログが描画されない／元ブックのウィンドウの裏に隠れる
- ユーザーからは「押すものが無いのに反応しない」＝完全なフリーズに見える
- 実際はExcelは**返事を待っているだけ**なので、永久に終わらない

設定は `約定を確認する = する` になっているので、**保有や注文がある日は毎回この状態になります。**
（保有2銘柄あり＝該当します）

---

## 3. `DoEvents` が更新処理に1つも無い

- `S2_バックテスト` には5日ごとに `DoEvents` があります
- しかし **`S2_更新`（`S2_Core`）には1つもありません**

Windowsは一定時間メッセージを処理しないアプリを「応答なし」と判定し、
ウィンドウを白く塗りつぶします。処理が動いていても**見た目は完全にフリーズ**します。

---

## 4. 出力がセル1個ずつ＋毎回 AutoFit

- `S2_OutRank` … 1行につき13回の `.Value` 代入
- `S2_OutTrades` … 1行につき11回＋文字色設定
- `S2_OutBacktest` … 資産推移で1行3回 × 日数分

自動計算がONのままだと、**この1回1回でブック全体が再計算されます。**
加えて `S2_FitSheet` が毎回 `ws.UsedRange.Font.Size` と `Columns.AutoFit` を実行します。
取引履歴が増えるほど重くなります。

→ 原因1（手動計算化）を直せば、ここは実用上ほぼ気にならなくなります。

---

## 対策（この2ファイルで直ります）

### 手順
1. `Mod_S2_Speed.bas` を取り込む
   VBE(Alt+F11) → ファイル → **ファイルのインポート** → `Mod_S2_Speed.bas`
2. `差し替えコード.txt` の【1】～【4】を、同じ名前の既存プロシージャと入れ替える
   - 【1】`Mod_S2_Data` の `S2_OpenSrc`  ← **最優先。ここだけでも効きます**
   - 【2】`Mod_S2_Screen` の `S2_Core`
   - 【3】`Mod_S2_Rules` の `S2_ConfirmFills`
   - 【4】`Mod_S2_Rules` の `S2_バックテスト`
3. 上書き保存 → Excelを再起動 → 【更新】ボタン

### 直る内容
- 元ブックを**必ず手動計算で開く**（原因1）
- 質問ダイアログを **`vbSystemModal` で必ず最前面**に出す（原因2）
- 進捗表示に `DoEvents` を入れて「応答なし」を防ぐ（原因3）
- 処理全体を手動計算にして書き込みを軽くする（原因4）
- エラーで抜けても計算方法・画面更新を必ず元に戻す

## それでも止まる場合（元ブック側の問題）

元ブックにRSS関数が入っているなら、**マクロ側では直せません。**
元ブック `OHLCV　明日売買　ボリンジャー送信.xlsm` を

- 全選択 → コピー → **値貼り付け** した「数値だけの別ブック」を作り
- 設定シートの `SRC_PATH` をそちらに向ける

これが一番確実で速くなります。

## おまけ（フリーズとは別の要注意点）

### バックテストが250日ではなく46日しか回っていない
バックテストシートに出ている通りです。

- `読み込む履歴日数(HIST_MAX) = 260` / `検証する日数(BT_DAYS) = 250`
- 200日移動平均の助走に204日使うので、残り46日しか検証できていない

→ **元ブックの履歴を455営業日分まで増やし、`HIST_MAX` を 460 にしてください。**
今の成績（46営業日・決済1回・勝率0%）は判断材料になりません。

### 自動更新の予約（Application.OnTime）が消せなくなる
`S2_予約解除` は変数 `gNext` を使って解除しますが、この変数は
VBAの中断・編集・エラーでリセットされます。そうなると**予約が解除できず、
Excelを閉じても勝手に起動する**状態になります。

→ `Mod_S2_Speed.bas` に **`S2_予約全解除`** を入れてあります。
おかしくなったら Alt+F8 → `S2_予約全解除` を実行してください。
（そもそも予約はWindowsのタスクスケジューラ経由の方が安全です）
