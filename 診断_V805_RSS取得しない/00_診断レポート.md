# V805「動かない / RSS取得しない」原因診断レポート

対象ファイル: `V805___.xlsm`
解析日: 2026-08-05
解析方法: xlsm を展開し、`xl/worksheets/*.xml`（全数式）、`xl/volatileDependencies.xml`（実際に登録されている RTD トピック）、`xl/vbaProject.bin`（VBA 全 61 モジュール）を静的解析。

---

## 0. 先に結論

**ブックのファイル自体は壊れていません。**

- RSS 数式は 6,227 セルすべて `_xll.RssMarket(...)` / `_xll.RssIndexMarket(...)` の形で正常に保存されている
- `#NAME?` は OHLCV 5 シートに 0 件
- 保存時の計算モードは「自動」（`<calcPr calcId="191029"/>` に `calcMode` 指定なし＝auto）
- OHLCV 5 シートの A 列コードと数式内リテラルコードの不一致 **0 件**、銘柄管理 B 列との不一致も **0 件**
- 直近の日次更新は 2026/8/4 分まで正常に入っている（E3 = 46238 = 2026/8/4）

したがって「RSS が取れない」のは **実行環境側の要因** か、**このブックが自分で仕込んでいる時限爆弾** のどちらかです。以下、可能性の高い順に並べます。

---

## 1. 【最有力】MarketSpeed II RSS アドインが読み込まれていない

全 RSS 数式は次の形で保存されています。

```
終値!C6   =_xll.RssMarket("5706","現在値")
始値!C5   {=_xll.RssIndexMarket("TOPX","始値")}
銘柄管理!C6 =_xll.RssMarket(B6,"銘柄名称")
```

`_xll.` は Excel が **「この関数は XLL アドインのもの」** と記録する印です。ブック内にはアドインへの参照（externalLink）は一切保存されず、**開いた瞬間に読み込まれている XLL アドインから名前解決** されます。解決できないと全セルが `#NAME?` になります。

確認する順番:

1. **MarketSpeed II を先に起動してログイン** → その後で Excel / ブックを開く
   （Excel を先に起動すると RSS アドインが登録されないケースが多い）
2. Excel の「ファイル → オプション → アドイン → 設定(Excel アドイン)」に
   MarketSpeed II RSS のチェックが入っているか
3. **「COM アドイン」ではなく「Excel アドイン(.xll)」側** を見ること
4. Excel の bit 数（32/64）と MarketSpeed II の bit 数が一致しているか
5. ブックを **保護ビュー**（インターネットからダウンロードしたファイル等）で開いていないか
   → 保護ビュー中はアドインも RTD も動きません。「編集を有効にする」＋「コンテンツの有効化」必須
6. Excel が **複数インスタンス** で起動していないか（RTD サーバは起動インスタンスに紐づく）

> 判定用マクロを `03_Mod_RSS環境診断.bas` に用意しました。実行すると
> アドイン解決可否 / 計算モード / RTD スロットル / 数式欠損数 をまとめて表示します。

---

## 2. 【最有力・その2】計算モードが「手動」で固定されている

RTD（RSS の実体）は **再計算が走らないと画面に反映されません**。計算モードが手動になっていると、MarketSpeed II 側が値を送っていても C 列は固まったままです。

このブックには **エラーハンドラを持たないまま `Application.Calculation = xlCalculationManual` にするプロシージャが 9 個** あります。実行中に一度でもエラーが出ると、**手動計算のまま復帰しません**。

| モジュール | プロシージャ | 復帰処理 |
|---|---|---|
| Mod_MS_TimeSeriesImport | `マーケットスピード過去データ取込` | ハンドラ無し |
| 日付ヘッダー整合 | `日付ヘッダー一括整合` | ハンドラ無し |
| Mod_SellExtrac | `S_抽出実行` / `S_抽出実行_RSS` | ハンドラ無し |
| Mod_売抽出_下降VWAP | `抽出実行_下降` | ハンドラ無し |
| Mod_買抽出_順張りVWAP | `抽出実行_順張り` | ハンドラ無し |
| **Mod_買抽出v13** | **`抽出実行`** | **ハンドラ無し** |
| Module7 | `修復_ALL` | ハンドラ無し |
| Module8 | `古い履歴を消去` | ハンドラ無し |
| Module9 | `TrimCore` | ハンドラ無し |

とくに `Mod_買抽出v13.抽出実行` は日常的に押すボタンです。ここで落ちると **その後 RSS が一切更新されなくなります。**

**即効の応急処置**: 数式タブ →「計算方法の設定」→「自動」。
または VBA イミディエイトウィンドウで `Application.Calculation = xlCalculationAutomatic`

あわせて `Application.RTD.ThrottleInterval` が `-1` になっていないかも確認してください（`-1` は「手動更新のみ」の意味で、RTD が自動で流れなくなります）。診断マクロで表示します。

## 3. 【設計上の時限爆弾】Workbook_Open が RSS 接続前に日次更新を走らせる

`ThisWorkbook`:

```vba
Private Const AUTO_ENABLED As Boolean = True

Private Sub Workbook_Open()
    ...
    gUnattended = True
    On Error Resume Next
    Call 日次更新_本日分      ' ← 開いた瞬間に走る
    On Error GoTo 0
    ...
End Sub
```

`Mod_日次更新.ExecuteDailyUpdate` は、

1. E:CY 列を F:CZ へ一括シフト
2. **E5:E505 を ClearContents（全銘柄の当日値を空に）**
3. C 列（RSS ライブ値）が数値かつ >0 の行だけ E 列へ書き戻し
4. 日付ヘッダをシフトし、**E3 に当日日付を書く**

という順序です。ところが **ブックを開いた直後は MarketSpeed II RSS がまだ 1 銘柄も値を返していません**（1,711 トピック / 291 銘柄の初期化に数十秒かかる）。結果:

- 手順 3 で書き戻せる行がほぼゼロ → **当日分が全銘柄「欠測」で確定**
- しかし手順 4 で E3 に当日日付だけは入る
- 次に手動で日次更新しても、冒頭の冪等性チェック
  `If CDate(e3) = bizDate Then ... 既に取込済` に引っかかり **その日はもう二度と取り込めない**

これが「V805 が動かない」体感の中心にある可能性が高いです。

さらに、**Module7（作者自身の緊急修復モジュール）の完了メッセージにこう書かれています**:

```
この後の手順:
 ① ThisWorkbook の Workbook_Open から
    「Call 日次更新_本日分」と OnTime 3行を無効化
```

**作者自身が「無効化しろ」と書いた対策が、V805 では実施されていません。**（`AUTO_ENABLED = True` のまま、`Call 日次更新_本日分` も OnTime 3 行も生きています）

また `日次更新_本日分` は時間窓（15:31〜翌 08:00）外だと **素の `MsgBox`**（`UI_Msg` ではない）を出します。日中にブックを開くと毎回モーダルが出て止まります。

→ 修正版を `01_ThisWorkbook_修正版.txt` に用意しました。

| 現在値 | 290 |
| 始値 | 288 |

| 安値 | 288 |
| 出来高 | 288 |

| 出来高加重平均 | 36 |
| 前日比 | 36 |
| その他 | 3 |
| **合計（重複除去後）** | **1,711** |

参照セル数は 3,902、数式総数は **6,227**。銘柄数は 291。

この規模だと接続完了まで相当な時間がかかり、**「開いた直後に値を読む」処理（＝上の §3）と組み合わさると確実に取りこぼします**。まず RSS が揃うのを待ってから処理を始める設計に変えるべきです。

## 5. 空コード行に RSS 数式が貼られたまま（無駄打ち）

| シート | RSS 数式のある行 | うちコード列が空の行 | ガード |
|---|---|---|---|
| **管理** | 458 行 (4〜461) | **415 行** | なし |
| **銘柄管理** | 488 行 (5〜505) | **200 行** (306〜505) | なし |
| 分析 | 204 行 | 9 行 | `IF(C3<>"",...)` あり |
| 売分析 | 204 行 | 9 行 | `IF(C3<>"",...)` あり |

管理シートは 1 行あたり 4 本（銘柄名称 / 現在値 / 出来高加重平均 / 前日比）なので、**約 1,660 本が空コードに対する問い合わせ**です。分析・売分析には `IF(C3<>"", ...)` のガードが入っているのに、管理・銘柄管理には入っていません。

対処: 管理・銘柄管理の RSS 数式も `=IF($B4="","",_xll.RssMarket($B4,"現在値"))` のようにガードで包む（`04_空行ガード適用.bas`）。

## 6. OHLCV 5 シートにゴミ行が 13 行残っている

A 列に銘柄コードでない値が入り、C 列の RSS 数式が消えている行:

```
行 25(A="45")  27("47")  31("53")  75("139")  102("191") 134("253")
149("280")     177("334") 205("386") 221("415") 228("421") 230("422") 245("436")
```

ThisWorkbook のコメントにある「汚染 13 銘柄を除去」の残骸です。銘柄管理側は空、C 列の RSS 数式も無いのに **A 列だけ値が残っている** ため:

- `Mod_日次更新` は `code <> "" And code <> "0"` で有効行と判定 → 毎日「欠測」にカウントされる
- `Mod_買抽出v13.抽出実行` も同じ判定で **13 行をスキャン対象に入れる**

→ A 列を消すべきです（`05_ゴミ行クリーンアップ.bas`）。

## 7. 「RSS 接続状態チェック」が誤診断する

`Mod_RSS接続状態.CheckRSSStatus`:

```vba
Dim v As Variant: v = closeWs.Cells(r, 5).Value   ' ← E列
```

**見ているのは E 列（＝昨日までの保存済み値）で、RSS ライブ値の C 列ではありません。**
コメントにも「終値!E6 (TOPIX の今日の終値)」と書かれていますが、E 列は日次更新が書き込んだ静的な値です。

結果:

- RSS が完全に切れていても E 列に過去値があれば **「[RSS接続中]」と表示される**
- 逆に §3 で E 列が空になった直後は、RSS が生きていても **「[RSS切断]」** と出る

診断ツールとして機能していません。→ `02_Mod_RSS接続状態_修正版.bas` で C 列を見るように直しました。

## 8. 「RSS式修復」マクロが壊れている（実行すると悪化する）

`Mod_RSS式修復_v2.OHLCV_RSS式修復_v2` が書き込む式:

```vba
ws.Cells(r, 3).Formula = "=@RssMarket($A" & r & ",""" & shName & """)"
ws.Cells(r, 4).Formula = "=IF(OR(C" & r & "=0,G" & r & "=0),"""",C" & r & "-F" & r & ")"
```

実際にシートに入っている正しい式:

```
C6  =_xll.RssMarket("5706","始値")            ← コード直書き（$A6 参照ではない）
D6  =IF(OR(C6=0,E6=0),"",C6-E6)               ← E列参照
```

問題点:

1. **D 列式の参照列が違う**（修復版は `G`/`F`、正しくは `E`/`E`）。実行すると **前日比列が全部壊れます**
2. C 列は既存が「コード直書き」なのに `$A{行}` 参照に変わる。A 列が文字列コードなので動きはしますが、混在すると保守不能
3. 最悪なのがこれ ↓

```vba
On Error Resume Next
If ws.Cells(r, 3).HasFormula = False Then
    ws.Cells(r, 3).Formula = "=@RssMarket(...)"    ' ← アドイン未ロードならここで 1004
    fixedC = fixedC + 1                            ' ← エラーでも次行なので加算される
End If
```

`On Error Resume Next` の下で代入直後にカウンタを足しているため、**書き込みが失敗しても「修復した」と報告します**（虚偽レポート）。「修復したのに直らない」の正体はこれです。

同じパターンが `Mod_RSS式診断.OHLCV_RSS式強制修復` にもあります。

→ 正しい式を書き、書き込み後に `HasFormula` で検証する版を `06_Mod_RSS式修復_v3.bas` に用意しました。

## 9. 銘柄の追加/削除/圧縮が RSS 数式を壊す

| プロシージャ | 問題 |
|---|---|
| `Sheet1.ClearOHLCVRow` | B 列を空にすると OHLCV 5 シートの **C 列（RSS 数式）ごと ClearContents** |
| `Mod銘柄管理.銘柄削除` | 同上（`ws2.Cells(foundRow, 3).ClearContents`） |
| `Mod銘柄管理.銘柄一覧_圧縮` | 銘柄管理 C 列を **`.Value` で読んで `.Value` で書き戻す** → RSS 数式が静的文字列に化ける。しかも銘柄管理だけ詰めて OHLCV 5 シートは詰めないので行対応がズレる |

一度削除した行に別銘柄を入れ直すと、C 列に数式が無いまま = **その行だけ永久に RSS が取れません**。§8 の修復マクロが存在する理由がこれです。

**`銘柄一覧_圧縮` は使わないでください。**

## 10. その他の細かい不具合

- **分析 / 売分析の 3 行目**: `C3` が `"TOPX"` なのに `_xll.RssMarket(C3,"現在値")` を呼んでいる。指数は `RssIndexMarket` でないと取れないので、E3:K3 は常にエラー/0
- **銘柄管理 B 列が数値型**: `5706` が数値として入っている。`285A` `485A` のような英字入り新コード（MS取込モジュールが対応を明記している）を入れられない／先頭 0 が落ちる
- **銘柄管理 B 列は 290 銘柄、OHLCV A 列は 287 銘柄** で 3 件ズレている
- **履歴が 74 列（E〜BZ, 2026/4/10〜8/4）しかない**のに、抽出マクロは `Cells(i,5)〜Cells(i,104)`（100 列）を読む。26 列が空
- **日付ヘッダの欠測日**: 7/16(木), 6/9(火), 6/1(月), 5/26(火) の 4 営業日が抜けている（7/20 海の日・GW・4/29 は正しく欠番）。日次更新が走らなかった日
- `modAutoGuard.AutoLog` が参照する `自動ログ` シートが存在しない（無害だがログが残らない）

## 復旧手順（この順番で）

1. **MarketSpeed II を起動・ログイン** → その後 Excel でブックを開く
2. 数式 →「計算方法の設定」→ **自動** を確認
3. `03_Mod_RSS環境診断.bas` を貼って `RSS環境診断` を実行 → アドイン解決可否を確定させる
4. `_xll` が解決できていれば C 列に値が入り始める。**30〜60 秒待つ**（1,711 トピック）
5. `01_ThisWorkbook_修正版.txt` を ThisWorkbook に貼り替え
   （＝ Module7 が指示していた「① Workbook_Open の無効化」を実施）
6. `05_ゴミ行クリーンアップ.bas` でゴミ 13 行の A 列を消す
7. C 列数式が欠けている行があれば `06_Mod_RSS式修復_v3.bas` の `OHLCV_RSS式修復_v3` で復元
8. `02_Mod_RSS接続状態_修正版.bas` で既存の `Mod_RSS接続状態` を差し替え
9. §2 の表にある 9 プロシージャに `On Error GoTo` + `Cleanup:` を追加（`07_計算モード復帰パッチ.md` 参照）
10. 空コード行の無駄打ちを止めるなら `04_空行ガード適用.bas`
